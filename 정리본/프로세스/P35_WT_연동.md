# [프로세스] W/T 연동

> 키워드: INV-WT · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「W/T」(적치·이동·피킹 W/T, W/T 생성·확정·취소), 「EWMS BIN 코드」(BIN 마스터·Stock Type·자동화구역·9011/9013·RCV3·RCV4), 「조직·재고관리체계」(PLANT·화주 맵핑·수신 PLANT별 실적), 「재고 수량」(가용재고·W/T 미확정을 예약으로 나타냄)
> **이름만 쓰는 묶음**: 「시스템」(EWMS), 「LOT·제조번호」(LOT), 「작업지시 체계」(Work·Task·전략 이력), 「AS/RS」(Bypass·출고대), 「WCS 위치」(셀), 「에러·사유코드」(통합 에러관리·Reject), 「단말」(파워유저), 「창고 기초속성」, 「출고 오더」(시간대별 출고 Type), 「입고 업무 용어」(용량 부족 배출), 「출고 업무 용어」(GTP)
> **이어지는 프로세스**: 앞 → P01 EWMS 작업정보 수신 / 함께 → P08 AS/RS 적치, → P10 AS/RS Bypass 이송, → P12 AS/RS 용량 부족 배출, → P31 출고완료 확정, → P26 W/T 취소 요청 / 뒤 → P39 재고대사 / 관련 → P29 수작업 GTP 출고, → P41 자동화 전환(WCS 처리로 생기는 BIN 변경), → P45 네트워크 단절 대응(EWMS 단절)

## 1. 범위
- EWMS에서 W/T를 받아 WCS 재고로 잡을 때 시작해, 작업 완료 후 W/T 확정 실적을 EWMS에 보내 가용재고가 될 때 끝난다 〔K18-F00.01, K18-F00.02, K18-F00.03〕

## 2. 흐름

### 2-1. 기본 흐름
1. (EWMS→WCS) W/T를 받는다. 그 재고는 W/T 생성 상태다(재고에 갖는 뜻은 「W/T」 묶음) 〔K18-F00.01〕
2. (WCS) W/T를 받을 때 W/T 작업 예약을 만든다. W/T 미확정을 예약으로 나타내는 뜻은 「재고 수량」 묶음 3.2에 있다 〔REQ-INV-WT-005〕
3. (WCS) 작업을 완료한다(예: AS/RS 최종 적치) 〔K18-F00.02〕
4. (WCS→EWMS) 완료를 통보한다 〔K18-F00.02〕
5. (WCS) W/T가 확정되면 W/T 작업 예약을 소진한다 〔REQ-INV-WT-005〕
6. W/T 확정 상태가 된다. 재고가 가용재고가 되는 뜻은 「W/T」 묶음에 있다 〔K18-F00.03〕

### 2-2. 확정을 보내는 때
- WCS가 EWMS에 확정을 보내는 때는 적치 완료, 3·4층 배출 완료, 출고확정, 도착 확정이다 〔REQ-INV-WT-005〕

| W/T | 확정 시점·처리 | 출처 |
|---|---|---|
| 적치 W/T | 적치 완료 때 확정한다 | G079 |
| 적치 W/T — 적치하지 못하고 3·4층으로 토출한 건(Reject·용량 부족 배출) | 도착 위치로 DEST BIN을 바꿔 확정한다 | G079 |
| 토출건 | RCV3을 확정 때 DEST BIN으로 쓴다 | G178 |
| 4층으로 토출한 팔레트 | RCV4를 확정 때 DEST BIN으로 쓴다 | G179 |
| 1층 → 3층 Bypass | EWMS가 처음부터 DEST BIN을 3층 출고대(9013·RCV3)로 주므로 그대로 확정한다 | G079 |
| 4층 → 3층 Bypass(이동 W/T) | WCS가 AS/RS를 통해 옮긴 뒤 도착할 때 확정한다 | G078 |
| 피킹 W/T | WCS가 재고를 할당해 작업을 지시하고, 출고확정 때 확정한다 | G080 |

### 2-3. 실적 송신
- (WCS→EWMS) 실적을 보낼 때 원래 수신된 PLANT별로 나눠 보낸다(3-2) 〔K07-F00.05, BR-MST-STK-007, REQ-MST-STK-007〕

## 3. 조건·규칙

### 3-1. W/T 유형과 BIN
- Bypass 1층 → 3층·1층 → 4층은 적치 W/T로, 4층 → 3층은 이동 W/T로 처리한다(W/T 종류별 생성 주체는 「W/T」 묶음) 〔G077, G078〕
- AS/RS에 넣으라는 입고는 자동화구역으로 지정한다 〔G035〕
- 입고장(9011·9013)은 AS/RS에 적치하지 못하고 다른 프로세스로 가는 경우에만 쓴다 〔G035, G174〕
- W/T 생성·확정·실적 송신 때 BIN 마스터의 Stock Type·BIN 값을 지정한다 〔REQ-MST-LOC-023〕
- WCS 처리 결과로 생기는 BIN 변경(GTP 잔량 등)은 해당 규칙대로 W/T 생성·확정을 함께 처리한다(→ P29 수작업 GTP 출고, → P41 자동화 전환) 〔BR-MST-LOC-036〕
- W/T 취소는 작업을 모두 완료한 뒤 업무 마감 시점에, 더 이상 작업해 출고할 수 없는 남은 수량에만 쓴다(→ P26 W/T 취소 요청) 〔G216〕

### 3-2. 실적의 PLANT
- EWMS 실적은 맵핑으로 합쳐 가공했어도 원래 수신된 PLANT별로 나눠 보낸다는 것과 그 까닭(EWMS W/T가 PLANT 기준)은 「조직·재고관리체계」 묶음에 있다. 이 프로세스는 그 규칙대로 보낸다 〔BR-MST-STK-007, REQ-MST-STK-007, K07-F00.05〕
- WCS는 W/T를 받을 때 받은 PLANT를 보존한다 〔REQ-MST-STK-007〕
- 실적 PLANT는 재고가 입고될 때의 PLANT가 아니라 해당 W/T에 수신된 PLANT를 따른다. 예: L175로 입고된 통합 재고를 L1UU W/T로 출고하면 L1UU로 보고한다 〔REQ-MST-STK-008〕

### 3-3. 확정 실적의 단위
- W/T 확정 실적은 LOT 단위가 아니라 수신한 W/T 단위로 취합(합산)한다 〔BR-INV-WT-012, REQ-INV-WT-005〕

### 3-4. 통합 Work의 PARTIAL 순차 반영
- 여러 원본 W/T(여러 PLANT의 W/T 포함)를 한 Work·Task로 묶어 처리한 뒤 일부만 처리(PARTIAL)되면, 실적 수량을 정해진 순서대로 원본 W/T 행에 순차적으로 채워 반영한다 〔BR-MST-STK-009, REQ-MST-STK-011, REQ-MST-STK-008, REQ-INV-WT-005, REQ-SYS-JOB-006, REQ-SYS-JOB-008〕
- 반영한 실적은 W/T·수신 PLANT 단위로 보낸다(PARTIAL 포함) 〔REQ-SYS-JOB-006, REQ-MST-STK-011〕
- 부족분은 W/T별로 표시한다 〔REQ-MST-STK-008〕
- 순서 규칙: ① 시간대 Type 마감이 빠른 W/T ② 같은 마감이면 EWMS 수신 일시가 빠른 W/T ③ 같으면 W/T 번호·행 번호 순 〔REQ-MST-STK-012〕
- 앞 행의 지시 수량을 모두 채운 뒤 다음 행으로 넘긴다. 남은 행은 미처리 수량으로 표시한다 〔REQ-MST-STK-012〕
- 순서 규칙은 창고 기초속성 변수로 바꿀 수 있다. 적용 결과는 전략 이력에 남긴다 〔REQ-MST-STK-012〕

## 5. 예외

### 5-1. 맵핑되지 않은 BIN 수신
- EWMS에서 받은 W/T·오더의 로케이션(BIN)이 WCS 셀–BIN 맵핑에 없으면 처리하지 않는다 〔K11-EX01, REQ-MST-LOC-036〕
- 수신 건을 보류하고 오류 이력으로 남긴다. 통합 에러관리의 인터페이스 오류 분류로 알람한다 〔K11-EX01, REQ-MST-LOC-036〕
- 맵핑을 등록한 뒤 보류된 수신 건을 다시 처리할 수 있어야 한다(창고 미등록 처리와 같은 방식) 〔K11-EX01, REQ-MST-LOC-036〕
- 이유: 보류하지 않으면 맵핑을 등록한 뒤에도 그 W/T를 다시 받을 방법이 없어 작업이 생성되지 않는다 〔REQ-MST-LOC-036〕

### 5-2. W/T 확정 실패
- 확정이 실패해도 설비 작업은 멈추지 않는다 〔REQ-INV-WT-005〕
- 통신 오류(응답 없음·타임아웃)는 자동으로 다시 보낸다 〔BR-INV-WT-014, K18-EX01, REQ-INV-WT-006, REQ-INV-WT-005〕
- 자동 재전송 횟수·간격의 기본값은 「창고 기초속성」 묶음 변수 목록에 있다 〔K18-EX01〕
- 일정 횟수 실패하면 파워유저에게 알람을 보낸다 〔REQ-INV-WT-005〕
- 업무 오류(EWMS 거부: W/T 없음·취소됨·수량 초과 등)는 다시 보내지 않고 바로 알람한다 〔BR-INV-WT-014, K18-EX01, REQ-INV-WT-006〕
- 실패 건은 다른 W/T 확정을 막지 않는다. 다른 확정은 계속 보낸다 〔BR-INV-WT-014, K18-EX01, REQ-INV-WT-006〕
- 같은 W/T의 후속 실적(PARTIAL, 통합 Work 원본 W/T 순차 반영)은 앞 실적이 성공할 때까지 기다린다 〔REQ-INV-WT-006〕
- 한도를 넘긴 건과 업무 오류 건은 「확정 실패」 상태로 두고, 통합 에러관리의 인터페이스 오류로 알람한다 〔REQ-INV-WT-006〕
- (파워유저) 수동 재전송 또는 수동 완료를 고른다. 수동 완료는 EWMS에서 직접 처리한 것을 확인한 뒤 재전송 대상에서 빼는 것이다 〔BR-INV-WT-014, K18-EX01, REQ-INV-WT-006〕
- WCS 재고는 되돌리지 않는다. 확정 시점에 이미 반영했기 때문이다 〔BR-INV-WT-014, REQ-INV-WT-006〕
- 차이는 재고대사로 찾아 보정한다(→ P39 재고대사) 〔REQ-INV-WT-006〕

### 5-3. EWMS 단절
- EWMS가 끊겨도 설비는 멈추지 않는다. W/T 확정·생성 요청은 복구 후 순서대로 보낸다(→ P45 네트워크 단절 대응) 〔REQ-EQP-ASRS-031〕

## 7. 미결
- 재료에 미결 기록은 없다.
