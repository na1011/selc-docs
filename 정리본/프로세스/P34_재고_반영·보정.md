# [프로세스] 재고 반영·보정

> 키워드: INV-UNT · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「재고 이력·관리단위」(입출고 이력·재고 이동 로그·재고 상태 이력·이력 유형 코드·재고 관리단위), 「재고 수량」(예약수량·보류수량·마이너스 불가·예약/보류 합계 상한), 「재고 운영 용어」(재고 보정 — WCS 단독 처리, EWMS 연동 없음)
> **이름만 쓰는 묶음**: 「시스템」(EWMS), 「LOT·제조번호」(변경 TASK번호·시리얼 이력 로그·LOT 속성 변경), 「W/T」, 「HU」, 「AS/RS」, 「BOX Shuttle」, 「GANTRY」, 「EWMS BIN 코드」(RCV9), 「팔레트」(팔레트 ID·팔레트갈이), 「출고 업무 용어」(디팔레타이징·MIXED 팔레타이징·GTP·이적·재할당·긴급 보충), 「입고 업무 용어」(디베닝·팔레타이징), 「WCS 위치」(셀·셀 상태)
> **이어지는 프로세스**: 앞 → 실적을 내는 각 프로세스(P08 AS/RS 적치, P16 BOX Shuttle 적치·인출, P23 GANTRY 출고, P28 3층 출고 구성, P31 출고완료 확정 등), → P39 재고대사, → P40 재고실사 / 뒤 → P35 W/T 연동, → P37 제조번호 수신·추적, → P13 설비 출고 불가 재할당 / 관련 → P06 HU PACK·UNPACK·SWAP, → P36 LOT 채번·속성 변경, → P22 GANTRY 사전·긴급 보충, → P27 3층 사전·긴급 보충

## 1. 범위
- 재고를 바꾸는 처리(설비 실적·출고 차감·관리단위 전환·재고 보정)가 들어와, 이력을 쌓고 재고에 반영할 때까지다 〔K17-F20.00, K17-F21.00, K17-F22.00, K17-F23.00, K17-F24.00〕
- 재고 보정은 사유 등록 → 이력 적재 → 재고 반영 순서다 〔REQ-INV-UNT-027〕

## 2. 흐름

### 2-1. 재고 보정
1. (WCS) 보정 사유를 등록한다 〔BR-INV-UNT-019, REQ-INV-UNT-027〕
2. (WCS) 이력을 쌓는다 〔BR-INV-UNT-019, REQ-INV-UNT-027〕
3. (WCS) 재고에 반영한다 〔REQ-INV-UNT-027〕
- 재고대사·재고실사 차이도 이 순서로 보정한다(→ P39 재고대사, → P40 재고실사) 〔BR-INV-UNT-019〕
- 보정의 발생 원인(재고대사 보정·재고실사 보정)을 가르는 이력 유형 코드는 「재고 이력·관리단위」 묶음 4절에 있다 〔BR-INV-UNT-019, REQ-INV-UNT-027〕

### 2-2. 재고 변경 뒤의 연계
- 재고가 바뀐 뒤 EWMS 실적·W/T, 시리얼 이력 로그, HU 연동이 뒤따른다(→ P35 W/T 연동, → P37 제조번호 수신·추적, → P06 HU PACK·UNPACK·SWAP) 〔K17-F18.00〕
- 어떤 연계를 할지는 이력 유형 규칙을 따른다 〔K17-F18.00〕
- EWMS 통보가 먼저 성공해야 하는 유형(LOT 속성 변경)은 → P36 LOT 채번·속성 변경.

## 3. 조건·규칙

### 3-1. 처리별로 남는 이력과 재고 변화

| 처리 | 남는 이력 | 재고 변화 | 출처 |
|---|---|---|---|
| AS/RS 입고 등록, 디베닝 RCV9 등록, BOX Shuttle 적치, 재고 보정(+) | 입출고 이력(증가) | 재고가 생기거나 늘고, 위치가 등록된다 | K17-F20.00 |
| 출고완료 확정, 3·4층 배출 차감, 재고 보정(−) | 입출고 이력(감소) | 재고가 줄거나 종료된다 | K17-F21.00 |
| AS/RS 적치·재입고, 설비 간 이송, GANTRY·BOX Shuttle 셀 간 이동 | 재고 이동 로그 | 팔레트 이동·BOX 셀 간 이동의 재고 변화는 「재고 이력·관리단위」 묶음 3.5 | K17-F22.00 |
| 디팔레타이징, 팔레타이징, MIXED 출고 구성, GTP 분할, 팔레트갈이, HU PACK·UNPACK, LOT 속성 변경 (전환) | 입출고 이력(from 출고 + to 입고, 같은 변경 TASK번호) | 관리단위·LOT가 바뀌고 총량은 유지된다 | K17-F23.00 |
| 예약 생성·소진·해제, 보류, 작업중, W/T 미확정·확정, 이적 중, 셀 상태 변경 | 재고 상태 이력 | 예약·보류 수량, 재고·셀 상태가 바뀐다 | K17-F24.00 |

### 3-2. BOX 단위 설비의 BOX 재고
- 적재 실적 때 적재 셀 기준으로 입고 이력을 쌓는다 〔REQ-INV-UNT-013〕
- 셀 간 이동이 완료되면 재고 이동 로그를 쌓는다 〔BR-INV-UNT-008, REQ-INV-UNT-013〕
- 그 결과로 BOX 재고가 목적 셀로 반영된다 〔BR-INV-UNT-008, REQ-INV-UNT-013〕

### 3-3. 관리단위 전환
- from 관리단위의 출고 이력과 to 관리단위의 입고 이력을 같은 변경 TASK번호로 함께 쌓는다 〔REQ-INV-UNT-017, K17-F23.00〕
- 왕복(BOX → 팔레트 → BOX → 출고 팔레트) 추적은 이력의 from → to를 이어 따라간다 〔REQ-INV-UNT-017〕
- 디팔레타이징 후 원팔레트 잔량은 원 팔레트에 남는다(AS/RS에 재입고할 때도 그대로다) 〔REQ-INV-UNT-018〕
- 원팔레트 잔량이 0이 되면 그 재고를 종료한다 〔REQ-INV-UNT-018〕

### 3-4. 출고 차감
- 출고 차감은 해당 예약을 소진하고 차감한다 〔REQ-INV-UNT-025〕

## 5. 예외
- 수량을 합산한 결과가 마이너스가 되면 처리하지 않는다 〔K17-EX02〕
- 같은 요청이 다시 들어오면(설비 실적 재전송 등) 성공한 요청은 한 번만 반영한다 〔K17-EX03, REQ-INV-UNT-025〕
- 실패한 요청은 다시 처리한다 〔K17-EX03, REQ-INV-UNT-025〕
- 재고 보정 감소로 예약이 재고를 넘으면, 넘는 예약을 해제하고 재할당·긴급 보충으로 넘긴다(→ P13 설비 출고 불가 재할당, → P22·P27 사전·긴급 보충) 〔K17-EX04, REQ-INV-UNT-025〕
- 재고 보정 감소로 보류가 재고를 넘으면, 넘는 보류를 줄인다 〔REQ-INV-UNT-025〕
