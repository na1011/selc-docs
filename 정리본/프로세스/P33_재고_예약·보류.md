# [프로세스] 재고 예약·보류

> 키워드: INV-RSV · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「재고 수량」(예약수량·보류수량·가용수량·작업 잠금·도착예정 수량·작업중 재고), 「작업지시 체계」(Task·Action·Workflow·전략 이력)
> **이름만 쓰는 묶음**: 「W/T」, 「LOT·제조번호」(LOT·변경 TASK번호), 「WCS 위치」(셀·셀 상태), 「재고 이력·관리단위」(관리단위·재고 이동 로그), 「출고 오더」(시간대별 출고 Type), 「할당 전략」, 「조직·재고관리체계」(화주·PLANT), 「창고 기초속성」, 「단말」(대시보드), 「GANTRY」, 「BOX Shuttle」, 「AS/RS」, 「출고 업무 용어」(재할당·이적·GTP·MIXED 팔레타이징), 「팔레트」(팔레트갈이)
> **이어지는 프로세스**: 앞 → P32 재고 할당, 뒤 → P42 작업지시 생성·실행, → P13 설비 출고 불가 재할당, → P39 재고대사, → P31 출고완료 확정

## 1. 범위
- 예약: 재고를 쓰는 Task를 만들 때 예약을 걸고, 실적으로 소진하거나 취소·정리로 해제할 때까지다 〔REQ-INV-RSV-013〕
- 보류: EWMS에서 보류재고 전환·해제 정보를 받아 보류수량에 반영할 때까지다 〔REQ-INV-QRY-008〕

## 2. 흐름

### 2-1. 예약 걸기 ~ 실적
1. (WCS Planning) 재고를 쓰는 Task(출고 할당·보충·이송·실사 등)를 만들 때 후보 재고를 조회한다. 조건은 가용수량 > 0, 셀 상태 정상, 작업 잠금 없음이다 〔K19-F00.01〕
2. (WCS Planning) Task를 만들 때 할당과 예약을 함께 처리한다 〔REQ-INV-RSV-002, REQ-INV-RSV-013〕
3. (WCS Planning) 예약 직전에 가용수량을 다시 확인한다. 실패하면 5절 「예약 경합」을 따른다 〔REQ-INV-RSV-002〕
4. (WCS Planning) 할당과 함께 예약(작업 유형·수량)을 건다 〔K19-F00.02〕
5. (WCS Planning) 팔레트 이동이면 작업 잠금을 함께 건다. 목적 셀에는 적치 예약과 도착예정 수량을 등록한다 〔K19-F00.02, REQ-INV-RSV-013〕
6. (WCS Planning→WCS Execution) 예약된 재고(관리단위·LOT·수량)를 담아 Task를 전달한다 (잠정 §9-7) 〔K19-F00.03〕
7. (WCS Execution→설비 ECS) Workflow에 따라 Action을 지시한다. Action을 보낸 뒤에는 예약을 회수(선점)하지 않는다 〔K19-F00.04〕
8. (설비 ECS→WCS Execution→WCS Planning) 실적을 받으면 출고·이동 이력과 예약 소진을 같은 변경 TASK번호로 함께 처리한다 〔K19-F00.05, REQ-INV-RSV-007〕
9. (WCS Planning) 도착예정 수량을 재고로 바꾸고 작업 잠금을 해제한다 〔K19-F00.05〕
10. (WCS) 작업 잠금은 Task가 완료되거나 취소될 때 해제한다 〔G114〕

### 2-2. 보류수량 반영
1. (EWMS→WCS) 보류재고 전환·해제 정보를 받는다 〔G116, BR-INV-QRY-005, REQ-INV-QRY-008, K36-F01.01〕
2. [미결 Q-104] (WCS) 대상 LOT를 식별한다. 식별 기준은 추가 협의 중이다 〔K36-F01.02〕
3. (WCS) 보류 전환 수량이 가용수량보다 크면 재고 처리 오류로 하고 반영하지 않는다 → (WCS→EWMS) 보류 오류를 통보한다(5절) 〔K36-F01.03〕
4. (WCS) 해당 제품의 LOT별 재고에서 보류수량을 바꾼다. 전환은 증가, 해제는 감소다 〔G116, BR-INV-QRY-005, REQ-INV-QRY-008, K36-F01.04〕
5. (WCS) 가용수량을 다시 계산한다 〔K36-F01.04〕
6. (WCS) 해당 LOT가 하나라도 속한 팔레트·셀 전체를 보류 대상으로 처리한다 〔K36-F01.05〕
7. (WCS) 같은 팔레트·셀의 다른 LOT 재고에 동반 보류를 건다(3-5) 〔BR-INV-QRY-012, REQ-INV-QRY-015〕

### 2-3. 예약 정리
1. (WCS) 주기적으로 정합성을 점검한다: ① 예약 합계 ≤ 재고수량 ② 종료·취소된 Task에 남은 예약(고아 예약) ③ 기준 시간을 넘긴 예약 〔REQ-INV-RSV-010〕
2. (WCS) 찾은 예약을 정리 대상으로 표시하고 대시보드에 알람을 보낸다 〔REQ-INV-RSV-010, K19-EX03〕
3. 예약은 자동으로 해제하지 않는다 〔BR-INV-RSV-005, REQ-INV-RSV-010, K19-EX03〕
4. (사용자) 정리 대상을 확인한 뒤 해제할지 유지할지 정한다 〔BR-INV-RSV-005, REQ-INV-RSV-010, K19-EX03, REQ-INV-RSV-013〕
5. (WCS) 처리자·사유를 예약 이력과 전략 이력에 남긴다 〔REQ-INV-RSV-010〕

## 3. 조건·규칙

### 3-1. 우선순위·선점
- 예약 사이의 우선순위는 시간대 Type 마감이 빠른 W/T가 앞선다 〔BR-INV-RSV-003〕
- 우선순위에 따른 예약 회수(선점)는 Action을 설비에 보내기 전의 Task까지만 허용한다 〔REQ-INV-RSV-008, REQ-INV-RSV-013〕
- Action을 보낸 뒤에는 회수하지 않는다 〔REQ-INV-RSV-008, K19-F00.04〕
- 선점된 Task는 재할당 대상으로 돌리고, 사유를 전략 이력에 남긴다 〔REQ-INV-RSV-008〕

### 3-2. 소진 시점과 예약 이동
- Task 예약은 Task가 끝날 때 소진한다 〔BR-INV-RSV-008〕
- 실적으로 소진하고, Task가 취소되면 해제한다 〔REQ-INV-RSV-013〕
- Workflow 중간 단계의 이동(예: 출고 인출 → 이송 셀)에서는 예약이 BOX를 따라 to 셀로 이어진다 〔BR-INV-RSV-008〕
- 할당받은 BOX를 출고 인출해 이송 셀로 옮길 때(BOX Shuttle·GANTRY 피킹호기 → 이송 셀 → MIXED) 그 Task의 예약을 이동 수량만큼 to 셀로 함께 옮긴다 〔REQ-INV-RSV-018〕
- 이 예약은 MIXED 완료 실적의 전환에서 소진하고, 새 출고 팔레트에 같은 W/T(Work)의 예약을 다시 만든다 〔REQ-INV-RSV-018, REQ-INV-UNT-028〕
- 다시 만든 예약의 작업 유형은 출고확정 대기다. 출고확정 때 소진하므로 그 사이 다른 작업에 할당되지 않는다 〔REQ-INV-UNT-028〕
- GTP 분할 팔레트·팔레트갈이 팔레트도 같은 방식이다 〔REQ-INV-UNT-028〕
- 보충 이동처럼 이동이 Task의 마지막 단계면 도착할 때 소진한다 〔BR-INV-RSV-008, REQ-INV-RSV-018〕

### 3-3. 관리단위 전환·셀 간 이동
- 관리단위 전환에서는 예약과 작업 잠금이 새 관리단위로 이어진다 〔REQ-INV-RSV-017〕
- BOX 셀 간 이동은 예약을 옮기지 않는다. 이동하는 BOX에는 이동 Task 자신의 예약만 건다 〔REQ-INV-RSV-017〕
- 출고 할당은 목적 셀에 도착한 뒤에 한다(GANTRY 보관호기, BOX Shuttle 적치 후 할당) 〔REQ-INV-RSV-017〕
- 할당 후 출고 인출처럼 Workflow 중간 단계의 이동은 3-2를 따른다 〔REQ-INV-RSV-017〕

### 3-4. 작업중 재고
- 작업중 재고는 작업지시를 만드는 시점에 가용재고에서 뺀다 〔G106〕
- 작업이 완료되면 다시 가용으로 돌린다(예: 재고실사 배출~재입고, → P40 재고실사) 〔G106〕

### 3-5. 보류 재고와 할당
- 보류 재고의 이동·전환을 막는 시점은 작업 생성·할당 단계다 〔REQ-INV-UNT-035〕
- 팔레트 단위로 움직이거나 전량 해체하는 처리(팔레트 출고·3층 전량 해체·GANTRY 디팔레타이징·AS/RS 셀 이동 등)는, 팔레트 안에 보류 재고가 하나라도 있으면 그 팔레트를 후보에서 뺀다(할당 전략 필터) 〔REQ-INV-UNT-035〕
- 이유: 빼지 않으면 고른 팔레트의 이동·전환이 거부되어 Task가 멈춘다 〔REQ-INV-UNT-035〕
- 동반 보류: 보류가 생기면 같은 팔레트·셀의 다른 LOT 재고도 출고 할당에서 뺀다 〔BR-INV-QRY-012, K36-EX02, REQ-INV-QRY-015〕
  - 다른 LOT 재고에 보류를 건다. 사유 = 동반 보류, 근거 = 원 보류, 수량 = 그 재고의 미예약 수량이다 〔REQ-INV-QRY-015, BR-INV-QRY-012〕
  - 그 재고의 가용수량은 0이 된다 〔REQ-INV-QRY-015, BR-INV-QRY-012〕
  - 원 보류가 해제되면 근거로 연결된 동반 보류를 함께 해제한다 〔BR-INV-QRY-012, K36-EX02, REQ-INV-QRY-015〕
  - 이유: 다른 LOT 재고가 가용으로 남으면 팔레트 출고·해체에 할당된 뒤 보류 재고 때문에 이동이 거부되어 Task가 멈춘다 〔REQ-INV-QRY-015〕

### 3-6. 정리 대상 판정
- 기준 시간은 예약 생성 시각이 아니라 해당 Task·Action의 마지막 진행 시각(실적·상태 변경)부터 잰다 〔BR-INV-RSV-007〕
- 기준 시간은 작업 유형별로 다르게 둔다 〔BR-INV-RSV-007〕

| 예약 | 정리 대상으로 표시하는 때 | 출처 |
|---|---|---|
| 출고 예약 | 해당 W/T의 시간대 Type 마감 시각을 넘기면 | REQ-INV-RSV-015 |
| 보충·이송·3층 배출·공팔레트 피킹 예약 | 마지막 진행 후 작업 유형별 기준 시간(N분)을 넘기면 | REQ-INV-RSV-015 |
| 재고실사 예약 | 실사 계획 종료 시각을 넘기면 | REQ-INV-RSV-015 |
| 종료·취소된 Task에 남은 예약(고아 예약) | 시간과 관계없이 바로 | REQ-INV-RSV-015 |

- 작업 유형별 기준 시간은 창고 기초속성 변수로 둔다 〔REQ-INV-RSV-015〕
- 표시한 뒤의 처리는 정합성 점검(2-3)을 따른다 〔REQ-INV-RSV-015〕
- 오래 유지되는 예약(이적 중·출고확정 대기 등)은 예약 정리 기준 시간에서 뺀다. 뺄 작업 유형의 목록은 7절 Q-136이다 〔REQ-INV-UNT-030〕

## 5. 예외

### 5-1. 예약
- 예약 경합(가용수량 재확인 실패): Task를 만들지 않고 다음 순위 재고로 다시 고른다 〔K19-EX01, REQ-INV-RSV-002〕
- 부분 실적: 실적 수량만 소진한다. 남은 예약은 Task가 계속되면 유지하고, 종료되면 해제한다 〔K19-F00.06, REQ-INV-RSV-007〕
- 실물 부족 보고: 부족분 예약을 해제한 뒤 재고 처리 오류를 표시하고 재할당한다 〔K19-F00.06, REQ-INV-RSV-007〕
- 실물 부족·출고 불가 보고 때는 재고대사에도 등록한다(→ P39 재고대사) 〔K19-EX02〕
- Task 취소·실패: 예약을 즉시 해제한다 〔K19-F00.07, REQ-INV-RSV-007〕
- 재할당은 원 예약 해제와 새 예약을 한 번에 처리한다 〔K19-F00.07, REQ-INV-RSV-007〕
- 고아 예약·기준 시간을 넘긴 예약: 정리 대상 표시·대시보드 알람, 사용자 확인 후 정리(2-3) 〔K19-EX03〕

### 5-2. 보류
- 이미 Action을 설비에 보낸 작업 중에 보류가 들어오면, 물리 이동은 이미 진행 중이므로 그 실적은 반영하고 알람을 띄운다(선점 한계와 같은 기준) 〔REQ-INV-UNT-035〕
- 이유: 반영하지 않으면 실물과 재고가 어긋난다 〔REQ-INV-UNT-035〕
- 보류 상한:
  - ⚠ 원문 불일치: 보류수량이 가용수량을 넘으면 재고 처리 때 오류로 한다 〔BR-INV-QRY-007〕
  - ⚠ 원문 불일치: 보류 전환 수량이 가용수량보다 크면 보류수량을 반영하지 않고 재고 처리 오류로 한다 〔REQ-INV-QRY-011, K36-EX01〕
  - 두 기록은 가용수량과 비교하는 값이 다르다(쌓인 보류수량 / 이번에 받은 전환 수량).
- 보류 전환·해제 처리 중 오류가 나면 EWMS에 오류를 통보한다(일단 정리, 통보 항목·방식은 추후 확정) 〔BR-INV-QRY-008, REQ-INV-QRY-012, K36-EX01〕

## 6. 기능·화면
- 정합성 점검과 정리 대상 확인은 2-3에 있다 〔REQ-INV-RSV-010〕
- 예약 상세를 재고조회에서 보는 기능은 → P38 재고조회.

## 7. 미결
- [추가 협의] Q-104: 보류재고 전환·해제를 받을 때 대상 LOT를 찾는 기준. EWMS는 WCS LOT 번호를 모르므로 화주·제품코드·LOT 속성값(Storage Location·Valuation Type·입고월 등) 중 무엇으로 찾을지 정해야 한다. 해제 수신·보류 범위·상한 오류는 결정됐다 〔Q-104〕
- [추후 정리] Q-136: 작업 유형별 정리 대상 기준 시간(N분)의 실제 값은 설비 리드타임 확정 후 채운다. 기준 시간을 적용하지 않을 작업 유형(이적 중·출고확정 대기 등)의 목록도 정해야 한다. 판정 방식·마지막 진행 시각 기준·작업 유형별·창고 기초속성 변수 관리는 결정됐다 〔Q-136〕
