# [프로세스] 네트워크 단절 대응

> 키워드: SYS-ARC · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「시스템」(Planning·Execution·SCP), 「작업지시 체계」(Task·Workflow·Action)
> **이름만 쓰는 묶음**: 「재고 운영 용어」(재고 스냅샷·재고대사)
> **이어지는 프로세스**: 앞 → P42 작업지시 생성·실행 · 뒤 → P39 재고대사

## 1. 범위
SCP–센터 사이 통신이 끊긴 때부터 복구 후 재고 차이를 확인할 때까지, 현장에서 무엇을 계속하나를 다룬다.
네트워크가 끊겨도 Planning과 Execution이 각각 독립적으로 작업을 수행할 수 있는 방안을 검토·설계한다 (잠정 §9-7)
네트워크 단절 시 Execution의 독립 수행 방안을 검토한다 (잠정 §9-7)

## 2. 흐름
1. (SCP–센터) 통신이 끊긴다
2. [확인필요] (WCS Execution) 독립 수행한다 (잠정 §9-7)
3. [확인필요] (WCS Execution) 이미 받은 Task 범위 안에서 Workflow·Action을 계속 수행한다 (잠정 §9-7)
4. [확인필요] (WCS Planning) 단절 중 신규 Task를 보관한다 (잠정 §9-7)
5. [확인필요] (WCS Execution→WCS Planning) 단절 중의 Task 진행·실적 보고는 복구 시 순서대로 전달한다 (잠정 §9-7)
6. [확인필요] 복구 후 재고 차이는 스냅샷 재고대사로 확인한다 → P39 재고대사

## 3. 조건·규칙
| 조건 | 처리 |
|---|---|
| [확인필요] 단절 중, 이미 받은 Task | Execution이 계속 수행한다 |
| [확인필요] 단절 중, 신규 Task | Planning이 보관한다 |

- 단절 시 독립 수행 범위(어떤 작업까지 계속할지)는 아직 정하지 않았다(7절 Q-110)

## 4. 주고받는 정보
- [확인필요] (WCS Execution→WCS Planning) 단절 중의 Task 진행·실적 보고는 복구 시 순서대로 전달한다(2절 5단계)
