# [프로세스] LOT 채번·속성 변경

> 키워드: MST-LOT · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「LOT·제조번호」(LOT·LOT 생성 전략·기타 LOT 속성·입고월·Valuation Type·LOT 속성 변경)
> **이름만 쓰는 묶음**: 「입고 오더」(입고예정정보), 「W/T」(적치 W/T), 「조직·재고관리체계」(창고코드·화주·PLANT·Storage Location·CDC), 「제품」(제품코드·WCS 자체 생성 제품), 「재고 이력·관리단위」, 「시스템」(EWMS)
> **이어지는 프로세스**: 앞 → P01 EWMS 작업정보 수신, → P02 일반입고, → P03 디베닝입고 / 뒤 → P34 재고 반영·보정 / 화면 → P38 재고조회 / 관련 → P42 작업지시 생성·실행(Work에 확정한 화주)

## 1. 범위
- LOT 채번: 입고정보를 받아 재고를 만들 때 쓸 LOT를 정할 때까지다
- LOT 속성 변경: 재고조회 화면에서 변경을 입력해 EWMS 통보 후 대상 수량을 새 LOT로 옮길 때까지다

## 2. 흐름

### 2-1. LOT 채번 (입고)
1. (EWMS→WCS) 입고정보(입고예정정보·적치 W/T)를 받는다. LOT 속성에 쓰는 항목은 4절에 있다
2. (WCS) 창고별 맵핑 규칙으로 입고정보 항목을 기타 LOT 속성 1~5에 맵핑한다
3. (WCS) 입고월을 가공해 LOT 속성(평택 CDC: 기타 LOT 속성3)에 적용한다. 입고월을 무엇으로 만드는지는 원문끼리 어긋난다(3-2)
4. (WCS) 해당 창고의 LOT 생성 전략에서 선택된 속성을 뽑는다. 필수·선택 속성이 채번에 미치는 영향은 「LOT·제조번호」 묶음에 있다
5. (WCS) 화주·Storage Location은 「조직·재고관리체계」 묶음의 맵핑 기준을 따른다. 화주는 Work를 만들 때 확정한 것이다(→ P42 작업지시 생성·실행 3-1)
6. (WCS) 재고를 만들 때 전략에서 선택한 LOT 속성값을 기존 LOT와 비교한다. 같은 조합이 있으면 기존 LOT를 쓰고, 없으면 그때 새로 채번한다

### 2-2. LOT 속성 변경
1. (사용자) 재고조회 화면에서 대상 재고·수량·변경할 속성(Valuation Type 등)·사유를 입력한다
2. (WCS→EWMS) WCS 재고를 처리하기 전에 변경 내용을 통보한다
3. (WCS) 통보가 성공하면 대상 수량을 변경된 속성 조합의 LOT로 옮긴다. 그 조합의 LOT가 없으면 새로 채번한다
4. (WCS) 원 LOT 수량을 차감하고 이력을 남긴다
5. (WCS) 통보가 실패하면 WCS 재고를 처리하지 않는다

## 3. 조건·규칙

### 3-1. LOT 채번
- LOT는 미리 만들지 않는다. 재고를 만들 때 같은 속성 조합의 LOT가 없을 때만 채번한다
- WCS 자체 생성 제품도 같다. 이때 LOT 생성 전략의 필수 속성으로 채번한다
- 상위 입고예정정보를 받을 때 LOT 속성(입고일자 등)이 맞게 적용되도록, 속성값을 정하는 규칙(입고일자 기준 시점)을 필요하면 커스터마이징할 수 있게 한다

### 3-2. 입고월의 근거
- ⚠ 원문 불일치: WCS는 입고예정정보를 받아 입고월을 가공해 만든다
- ⚠ 원문 불일치: WCS는 입고정보(입고예정정보·적치 W/T)의 입고일자로 입고월을 가공한다
- [미결 Q-175] 같은 기록들에 「입고예정정보 활용 = 입고 PLAN만」이 함께 적혀 있어, 입고예정정보로 입고월을 만드는 것과 충돌한다. 입고월을 적치 W/T로 만드는지 확인 중이다(7절 Q-175)

### 3-3. LOT 속성 변경
- LOT 속성 변경이 파손 외에도 여러 사유로 생긴다는 것은 「LOT·제조번호」 묶음에 있다
- 창고 운영 중 파손이 나면 LOT 속성 변경 기능으로 대상 재고의 Valuation Type을 바꾸고, 변경 내용을 EWMS에 통보한다
- WCS에서 Valuation Type 변경이 생기면 EWMS에 통보한다
- EWMS 통보 성공이 먼저 필요한 유형이다. 통보를 마친 뒤에 WCS 재고에 반영한다
- 대상 수량만 변경된 속성 조합의 LOT로 옮긴다. 같은 조합의 LOT가 있으면 그것을 쓴다
- 변경 전·후 LOT·수량·사유·작업자·일시를 이력으로 남긴다

## 4. 주고받는 정보

| 송신→수신 | 시점 | 업무 항목 |
|---|---|---|
| EWMS→WCS | 입고정보(입고예정정보·적치 W/T) 수신 때 — LOT 속성에 쓰는 항목 | 창고코드, PLANT(→ 화주), 제품코드, Storage Location, Valuation Type, 입고일자(→ WCS가 입고월 가공) |
| WCS→EWMS | WCS에서 LOT 속성(Valuation Type)을 바꿀 때, WCS 재고 처리 전 | 변경 내용. [미결 Q-106] 통보 항목은 추후 결정한다. 통보가 성공해야 WCS가 처리한다(2-2) |

## 5. 예외
- 창고 운영 중 파손: LOT 속성 변경(Valuation Type)으로 처리하고 EWMS에 통보한다(3-3)
- EWMS 통보 실패: WCS 재고를 처리하지 않는다(2-2)

## 6. 기능·화면
- LOT 속성 변경은 재고조회 화면에서 처리한다(→ P38 재고조회)
- [확인필요] LOT 속성 변경 때 사유 코드를 필수로 입력받는다
- [확인필요] 인터페이스 실패 건은 실패 사유와 함께 화면에 표시해 다시 시도할 수 있게 한다

## 7. 미결
- [추후 정리] Q-106: LOT 속성 변경을 EWMS에 통보할 항목, 사유 코드 관리·실패 재시도 채택 여부
- Q-106에서 이미 정한 것: 처리 방식, 다양한 사유, 재고조회 화면에서 처리, 통보 후 처리 순서(2-2·3-3·6절)
- [미결 Q-175] 입고월을 적치 W/T로 만드는지 확인해야 한다. 입고예정정보로 입고월을 만든다는 LOT 쪽 기록(규칙 1건·요구 2건. 두 요구는 원문 상태 확정)과 충돌한다(3-2)
- Q-175에서 이미 정한 것: 입고예정정보는 입고 PLAN 수립에만 쓴다(「입고 오더」 묶음)
