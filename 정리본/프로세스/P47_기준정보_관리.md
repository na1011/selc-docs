# [프로세스] 기준정보 관리

> 키워드: MST · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「조직·재고관리체계」(PLANT·화주·창고 맵핑), 「창고 기초속성」(변수·기본값), 「WCS 위치」(존·로케이션·셀, 셀 코드), 「에러·사유코드」(맵핑·통합 에러코드 설정), 「차량·도크」(DOCK 기준정보 항목), 「LOT·제조번호」(LOT 생성 전략·기타 LOT 속성·보관/출고 체크), 「할당 전략」(전략 칸·위치 규칙)
> **이름만 쓰는 묶음**: 「단말」(파워유저), 「시스템」, 「GANTRY」, 「W/T」, 「출고 업무 용어」(사전 보충), 「거래처·인도처」(거래처 마스터·거리유형), 「설비 공통·설비사」(설비 기준정보·설비사), 「작업지시 체계」(Workflow·전략 이력·프로세스 유형), 「재고 수량」(작업 잠금·잔량), 「재고 이력·관리단위」(이력 유형 코드), 「운반 설비」(ATL)
> **이어지는 프로세스**: 뒤 → P42 작업지시 생성·실행, P32 재고 할당, P36 LOT 채번·속성 변경, P20 출고 배치 편성, P44 설비 에러·Reject 처리, P49 차량 입출차 · 관련 → P48 제품마스터 수신·관리, P18 GANTRY 호기 운영(인도처 매핑)

## 1. 범위
WCS 사용자가 기준정보를 화면에서 등록·수정하는 일과, 그 값을 언제부터 적용하고 어떻게 검증·기록하나를 다룬다. 대상은 13가지다(3절).
각 기준정보가 어떤 칸·속성을 갖는지는 그 대상의 묶음에 있다. 이 문서는 칸 목록을 다시 적지 않는다.
제품마스터의 수신·관리는 → P48 제품마스터 수신·관리, GANTRY 호기별 인도처 매핑은 → P18 GANTRY 호기 운영에 있다.

## 2. 공통

### 2-1. 적용 시점
여러 기준정보가 「변경은 진행 중인 처리에 영향을 주지 않고, 이후 시작하는 처리부터 적용한다」는 같은 원칙을 쓴다

| 대상 | 진행 중인 것 | 새 값 적용 시작 |
|---|---|---|
| 창고 기초속성 | 진행 중인 작업에 영향을 주지 않는다 | 변경 이후 시작하는 처리부터 |
| Workflow 설정 | 진행 중 Task에 영향을 주지 않는다 | 이후 시작하는 Task부터 (창고 기초속성과 같은 원칙) |
| PLANT–화주 맵핑 | 이미 생성된 Work·LOT·재고의 화주는 바꾸지 않는다 | 이후 생성되는 Work부터 |
| 할당 전략 | 진행 중 Task는 생성 당시 전략을 유지한다 | (원문에 따로 없음) |
| 위치 규칙 | 진행 중 Task는 생성 당시 규칙을 유지한다 | (원문에 따로 없음) |

- 제품마스터의 경로 결정 속성도 같은 원칙이다 → P48 제품마스터 수신·관리

### 2-2. 바꾸기 전에 확인하기
| 대상 | 바꾸기 전에 보여 주는 것 |
|---|---|
| 할당 전략 | 시뮬레이션 — 현재 미할당 W/T·사전 보충 대상으로 기존·신규 전략의 결과를 비교한다(선택 LOT·팔레트, 잔량 발생, 보충 작업 수) |
| 위치 규칙 | 저장 전 미리보기 — 후보 셀 수, 빠지는 재고·진행 중 Work |
| PLANT–화주 맵핑 | 영향받는 재고(바뀐 PLANT가 속했던 화주의 재고) 목록 |

### 2-3. 변경 이력
| 대상 | 남기는 것 |
|---|---|
| 할당 전략 | 변경 내역을 전략 이력에 남긴다 |
| 위치 규칙 | 변경 이력과 버전을 남긴다 |
| [확인필요] 도착 지연 기준 시간(설비) | 바뀐 값을 변경 이력으로 남긴다 |

- 제품마스터 변경 이력은 → P48

### 2-4. 등록되지 않은 값을 만났을 때
대상마다 처리가 다르다. 자세한 것은 각 자리에 있다.

| 대상 | 처리 요지 | 있는 곳 |
|---|---|---|
| PLANT 맵핑 | 보류하고 알람, 맵핑 등록 뒤 다시 처리 | 3-3 |
| 창고 기초속성 변수 | 변수 정의 기본값을 쓰고 경고, 기본값도 없으면 오류 | 3-4 |
| 에러코드 | 원래 코드로 기록하고 「미등록 에러」 알람, 미맵핑 목록에 올림 | → P44 §5 |
| DOCK | 처리는 계속하고 경고, 미등록 DOCK 목록에 올림 | → P49 §5 |

### 2-5. 사용 여부
- 기준정보 공통의 사용 여부 규칙은 원문에 없다.

## 3. 대상별

### 3-1. 창고
1. (WCS) 창고 관리 화면에서 창고 마스터를 등록·수정한다
2. (WCS) 하위 기준정보를 창고에 소속시켜 등록한다
- 추가되는 창고도 개발 변경 없이 화면 등록으로 운영에 포함한다. 창고 관리 화면은 이에 대비해 둔다
- 신규 창고를 등록하면 창고 기초속성 변수가 기본값으로 생긴다 → 3-4

### 3-2. 화주
1. (WCS) 화주 마스터를 등록한다

### 3-3. PLANT 맵핑
1. (WCS) PLANT 관리 화면에서 PLANT코드별 맵핑(화주·창고)을 등록·수정한다. 항목과 맵핑 예는 「조직·재고관리체계」 묶음에 있다
2. 등록한 맵핑으로 EWMS 수신 시 창고를 식별하고, Work 생성 시 화주를 정한다 → P01 EWMS 작업정보 수신, P42 작업지시 생성·실행
- PLANT 관리 화면은 창고별 화면이 아니라 공통 기준정보 화면으로 둔다(화주를 창고 아래가 아닌 공통으로 관리하는 것은 「조직·재고관리체계」 묶음)
- 맵핑이 없는 데이터를 받으면 보류하고 알람을 띄운다. 맵핑을 등록한 뒤 다시 처리한다

**맵핑을 바꿀 때** (적용 시점은 2-1, 영향 재고 목록은 2-2)
1. (파워유저) 영향받는 재고에 대해 화주 변경 재고 처리를 실행할 수 있다
2. (WCS) 화주 변경 재고의 LOT를 다시 채번하고 이력을 남긴다(화주가 LOT 필수 속성인 것은 「LOT·제조번호」 묶음) → P36 LOT 채번·속성 변경
- EWMS 연계는 하지 않는다. 맵핑이 바뀌어도 EWMS 재고가 바뀌지 않는 까닭은 「조직·재고관리체계」 묶음 3-2에 있다
- 화주 변경 재고 처리를 두는 이유: 맵핑만 바꾸면 기존 재고가 새 화주 Work에 할당되지 않아 출고가 막힌다

### 3-4. 창고 기초속성
1. (WCS) 창고 관리 화면에서 창고를 등록한다 → 3-1
2. (WCS) 신규 창고를 등록하면 기초속성 변수를 기본값으로 생성한다. 창고를 추가할 때 누락 없이 설정하기 위해서다
3. (WCS) 창고 기초속성관리 화면에서 해당 창고의 제어 옵션 변수와 값을 창고별로 등록·수정한다
- 프로세스가 실행할 때 그 창고의 기초속성 변수를 읽어 동작을 정한다는 것은 「창고 기초속성」 묶음에 있다

**변수 누락 처리**
| 경우 | 처리 |
|---|---|
| 변수 정의를 새로 추가함 | 등록된 모든 창고에 기본값으로 생성한다 |
| 프로세스 실행 중 해당 창고에 값이 없음 | 변수 정의의 기본값을 쓰고 경고를 남긴다 |
| 기본값도 없는 변수 | 이것만 오류로 처리한다 |

- 오류는 통합 에러관리로 알람한다 → P44 설비 에러·Reject 처리
- 값이 없을 때 모두 오류로 처리하면 그 변수를 쓰는 프로세스가 모두 멈추기 때문이다

### 3-5. 거래처
1. (WCS) 거래처 마스터 화면에서 TC센터 거래처를 직접 등록·수정한다. 거래처 마스터의 칸, 그리고 EWMS와 거래처 인터페이스를 하지 않는다는 것은 「거래처·인도처」 묶음에 있다
2. (WCS) 거래처별 거리유형을 거래처 마스터 화면에서 지정·수정한다. 값과 쓰임(출고 배치 편성의 기준)은 「거래처·인도처」 묶음에 있다 → P20 출고 배치 편성
- 거래처 마스터 화면에서 미지정 거래처(신규 등록 거래처 포함)를 골라 거리유형을 지정한다. 「미지정」의 뜻은 「거래처·인도처」 묶음에 있다
- GANTRY 호기별 인도처 매핑은 → P18 GANTRY 호기 운영

### 3-6. 위치
- (WCS) 기준정보 화면으로 존 관리, 로케이션 관리, 셀 관리를 창고별로 제공한다
- 위치셀을 등록할 때 셀 코드 포맷을 설비 유형별 패턴(기준정보)으로 검증한다
  - 패턴 하나로 검증하면 주소 체계가 다른 설비사(「WCS 위치」 묶음 3-1)의 셀 등록이 거부되기 때문이다
- 셀별 피킹 우선순위를 화면에서 지정·수정한다
  - 피킹 우선순위를 할당에 쓰는 순서는 → P23 GANTRY 출고, P28 3층 출고 구성

### 3-7. 설비
- (WCS) 자동화 설비를 설비 기준정보로 등록·수정·조회한다
- [확인필요] 운영자가 화면에서 도착 지연 기준 시간 값을 바꾼다 (이력은 2-3) → 쓰는 곳 P43 팔레트 작업 상태 추적

### 3-8. 에러코드
1. (WCS 기준정보) 설비가 감지하는 에러코드를 설비사별로 받아 일괄 정리한다
2. (WCS 기준정보) 설비사별 에러코드를 취합해 통합 에러 기준정보에 등록한다
   - 등록하는 것: 원래 에러코드 → 통합 에러코드 맵핑과 통합 에러코드별 설정. 칸은 「에러·사유코드」 묶음에 있다
   - 통합 에러코드마다 어떤 후속 처리를 할지도 여기서 고른다 → P44 3-1
- 통합 에러코드·맵핑 관리 화면(PC): 미맵핑 코드 목록을 조회하고, 엑셀 업로드로 일괄 등록한다
- 미맵핑 코드가 목록에 오르는 경로는 → P44 §5

### 3-9. DOCK
- (사용자) DOCK 기준정보를 등록·수정하는 화면을 WCS가 제공한다
- DOCK 기준정보가 EWMS DOCK 데이터와 같아야 한다는 것은 「차량·도크」 묶음에 있다
- [미결 Q-181] 같게 유지하는 방법(사용자 등록 후 대사 / EWMS 코드 목록 제공)은 정하지 않았다
- WCS DOCK 기준정보에 1층 출고 DOCK 22개를 등록한다. 그중 ATL이 장착된 2개 DOCK은 ATL 설치 여부(센싱 대상)로 표시하고 구분을 입출고 겸용으로 둔다
- 차량 흐름에서 미등록 DOCK이 발견되면 미등록 DOCK 목록에 오르고, 사용자가 등록한다 → P49 §5

### 3-10. LOT 생성 전략
- LOT 생성 전략은 창고별로 별도 관리 화면에서 관리한다
- 같은 화면에서 창고별로 LOT 생성 전략, 기타 LOT 속성의 속성명, 입고정보 항목 맵핑 규칙을 함께 관리한다. 평택 맵핑 값은 「LOT·제조번호」 묶음에 있다
- 이 화면에서 선택한 속성별로 보관 체크·출고 체크 사용 여부도 함께 설정한다
- 출고 체크 설정이 Work 가공에 쓰이는 법은 → P42 3-1

### 3-11. 할당 전략 (위치 규칙 포함)
1. (WCS 사용자·파워유저) 프로세스 유형별 할당 전략을 등록·변경한다. 칸은 「할당 전략」 묶음에 있다
   - 바꾸기 전 시뮬레이션은 2-2, 적용 시점은 2-1, 전략 이력은 2-3
- 위치 규칙 변경은 운영 시간 외에 파워유저가 한다
- 위치 규칙 화면: 존 > 로케이션 > 셀 트리에서 포함·제외를 체크하고, 물려받은 값과 덮어쓴 값을 구분해 표시한다
- 할당 전략을 쓰는 공통 단계는 → P32 재고 할당

### 3-12. Workflow 설정
- 적용 시점은 2-1이다
- 프로세스마다 연결된 Workflow는 프로세스 통합 관리 화면에서 보고 수정한다 → 3-13

### 3-13. 프로세스 정의 (프로세스 통합 관리 화면)
- 프로세스 유형 코드 목록을 한 화면에서 관리한다
- 프로세스마다 다음을 함께 보여 주고 수정할 수 있게 한다: ① 연결된 할당 전략 ② Workflow ③ 우선순위(마감 순·긴급 보충 우선 등) ④ 예약·작업 잠금 여부 ⑤ 이력 유형 코드 ⑥ 관련 창고 기초속성 변수
- 같은 설정이 여러 화면에 흩어지지 않게 하는 단일 진입점이다

## 4. 주고받는 정보
- 이 문서의 등록·수정은 화면에서 한다. 거래처는 EWMS와 주고받지 않는다(3-5). DOCK은 EWMS와 같은 데이터를 유지하는 방법이 미결이다(3-9, Q-181).

## 5. 미결
- [미결 Q-181] EWMS와 같은 DOCK 데이터를 보장하는 방법(사용자 등록 후 대사 / EWMS 코드 목록 제공). 이미 정한 것: 사용자 등록, EWMS와 같은 데이터, DOCK 기준정보 항목, 정합 채택
- 설비사별 에러코드 일괄 정리는 Q-211(「에러·사유코드」 묶음)이다 → P44 §7
