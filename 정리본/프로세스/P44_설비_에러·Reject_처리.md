# [프로세스] 설비 에러·Reject 처리

> 키워드: SYS-ERR · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「에러·사유코드」, 「단말」, 「설비 공통·설비사」
> **이름만 쓰는 묶음**: 「시스템」, 「BOX Shuttle」, 「AS/RS」, 「로지스올 입고 설비」, 「W/T」, 「WCS 위치」, 「입고 업무 용어」, 「팔레트」, 「작업지시 체계」(Task), 「재고 운영 용어」(재고대사), 「출고 업무 용어」(재할당·긴급 보충)
> **이어지는 프로세스**: 앞 → 에러·Reject가 생기는 각 업무(P02 일반입고, P03 디베닝입고, P07 수작업 영역 팔레트 운반, P11 3층 출고대 도착 팔레트 처리, P16 BOX Shuttle 적치·인출 등), P47 기준정보 관리(에러코드 등록) · 뒤 → P13 설비 출고 불가 재할당, P22 GANTRY 사전·긴급 보충, P27 3층 사전·긴급 보충, P39 재고대사, P26 W/T 취소 요청, P42 작업지시 생성·실행 · 관련 → P46 단말 화면·알림(3층 출고대 도착 팔레트 판단 화면)

## 1. 범위
설비 에러가 WCS에 들어온 때부터 후속 처리를 실행하고 조치를 마칠 때까지다. Reject는 등록된 뒤 사후 처리를 마칠 때까지다.
에러가 들어오면 연결된 메시지를 작업자에게 전달하고 후속 처리(Reject 등록, 재고 오류 표시, 재할당, Task 보류 등)를 잇는다
각 업무의 개별 예외 처리(재할당·긴급 보충 등)는 그 업무 프로세스에 있다. 이 문서는 에러가 들어온 뒤의 공통 처리와 Reject 사후 처리만 다룬다

## 2. 흐름

### 2-1. 에러가 들어온 뒤의 공통 처리
1. (ECS→WCS) 에러를 보고한다: 설비사, 설비·호기, 원래 에러코드, 대상(팔레트 ID·BOX 식별자), 발생 위치, 관련 작업, 발생 시각
2. (WCS) 맵핑으로 통합 에러코드를 정한다 — 맵핑이 없으면 5절
3. (WCS) 에러 이력을 등록한다. 이력 항목은 「에러·사유코드」 묶음에 있다
4. (WCS→WCS PDA·대시보드·파워유저) 작업자 전달 메시지·처리방법 메시지를 알림 대상에 표시한다
5. (WCS) 코드에 연결된 후속 처리를 실행한다
   - 자동 실행형은 바로 실행한다
   - 작업자 확인형은 작업자가 WCS PDA·PC에서 확인한 뒤 실행한다
6. (WCS) 후속 처리의 실행 결과(성공·실패)를 이력으로 남긴다
7. (작업자·WCS) 조치를 마치면 에러 상태를 종료하고, 조치자·시각·결과를 이력으로 남긴다

### 2-2. Reject 사후 처리 (미처리 → 조치 중 → 완료)
1. (WCS) Reject를 공통 Reject 이력에 등록한다. 에러의 후속 처리 「통합 Reject 등록」이 이 등록이다
   - 이력 항목과 상태 값(미처리/조치 중/완료)은 「에러·사유코드」 묶음에 있다
   - 적치 W/T가 없으면 W/T 연결 여부를 「W/T 미연결」로 표시한다
2. (작업자, WCS PDA) 미처리 목록(발생 구분 필터)에서 대상을 고르고 스캔한다
3. (작업자, WCS PDA) 같은 화면에서 상세를 보고 조치한다. 고를 수 있는 조치는 3-2
4. (WCS) 조치자·시각·결과를 이력으로 남긴다. PC·대시보드에서 같은 이력을 조회한다

## 3. 조건·규칙

### 3-1. 에러 후속 처리
- 후속 처리는 다음 중에서 고른다. 자동 실행과 작업자 확인 후 실행으로 나뉜다

| 후속 처리 | 처리하는 곳 |
|---|---|
| ① 통합 Reject 등록 | 이 문서 2-2 |
| ② 재고 처리 오류 표시·재고대사 대상 등록 | → P39 재고대사 |
| ③ 재할당·긴급 보충 | → P13 설비 출고 불가 재할당, P22 GANTRY 사전·긴급 보충, P27 3층 사전·긴급 보충 |
| ④ Task 보류·재지시·취소 | → P42 작업지시 생성·실행 |
| ⑤ 설비 운영 상태 반영 | → P42 작업지시 생성·실행(작업 배정) |
| ⑥ EWMS 통보(W/T 취소 요청 등) | → P26 W/T 취소 요청 |

- 이 목록은 기본값이고, 에러코드별로 고른다
- 후속 처리는 기존 처리 기능을 쓴다
- 다른 설비도 같은 방식으로 에러코드별 연결을 정한다
- BOX Shuttle의 투입 거부·적치 실패·인출 실패 등 예외는 설비 에러코드로 받아 이 처리(통합 에러관리)의 에러코드별 처리로 다룬다

### 3-2. Reject 처리
- 모든 Reject를 발생 위치·설비와 관계없이 WCS PDA의 통일된 화면 하나에서 처리한다는 것은 「단말」 묶음에 있다
- 이 화면에서 조회·조치하는 Reject: 디베닝 BCR 검수 REJECT, 1층 입고대 Reject(ECS 에러 코드, 출고대 배출), 수작업 영역 팔레트 운반 중 Reject 등
- 1층 입고대 투입 전 오류(후진 배출)는 통합 Reject 대상에서 뺀다. PC에서 입고대 오류 이력으로 조회한다
- 발생 구분별로 허용 조치를 설정한다. 조치 유형 공통 코드는 「에러·사유코드」 묶음에 있다
- 허용 조치 기본값

| 발생 구분 | 허용 조치 |
|---|---|
| 3층 출고대 팔레트(1층 입고대 Reject·용량 부족·팔레트 유형 불일치·적치 W/T 없음) | 출고 수작업 영역 이동 / 3층 입고대 재투입 / 보류 |
| 디베닝 BOX | 확인 결과 입력 후 재투입(BCR 재검수) / 보류 |

- W/T 미연결 팔레트에서 재투입을 고르면 다시 배출된다는 경고를 띄운다

## 4. 주고받는 정보
| 송신→수신 | 시점 | 업무 항목 |
|---|---|---|
| ECS→WCS | 설비 에러 감지 시 | 설비사, 설비·호기, 원래 에러코드·메시지, 대상(팔레트 ID·BOX 식별자), 발생 위치, 관련 작업 번호, 발생 시각 |
| ECS→WCS | 에러 해제 시 | 설비·호기, 원래 에러코드, 해제 시각 |
| WCS→WCS PDA·대시보드 | 에러 발생·후속 처리 실행 시 | 통합 에러코드, 작업자 전달 메시지, 처리방법 메시지, 대상·위치 |
| WCS→EWMS | 후속 처리가 EWMS 통보인 경우 | 해당 통보 항목(W/T 취소 요청 등) |

## 5. 예외
| 경우 | 처리 |
|---|---|
| 맵핑 없는 에러코드를 받음 | 원래 코드로 기록한다 |
| 〃 | 「미등록 에러」로 알람한다 |
| 〃 | 미맵핑으로 표시하고, 통합 에러코드·맵핑 관리 화면의 미맵핑 목록에 올린다 → P47 기준정보 관리(에러코드) |
| 후속 처리 실행 실패 | 재시도한 뒤 알람한다 |
| 〃 | 작업자가 수동으로 다시 실행할 수 있게 한다 |

- ⚠ 원문 불일치: 같은 에러가 반복되면 억제 시간 안에는 알림을 묶고 건수만 올린다
- ⚠ 원문 불일치: 같은 설비·같은 코드가 억제 시간 안에 반복되면 알림을 묶고 건수만 올린다

## 6. 기능·화면
- 에러 발생 현황·이력 조회(PC·대시보드): 설비·코드·등급·기간 필터, 발생 빈도 집계
- WCS PDA 에러 알림·조치: 통합 Reject 화면과 같은 틀(목록 → 스캔 → 처리방법 확인 → 조치)
- 통합 Reject 화면: 미처리 목록 → 스캔 → 상세·조치가 한 화면 흐름이다
- 3층 배출라인 Bypass 판단도 통합 Reject 화면과 같은 틀을 쓴다
- 3층 출고대 도착 팔레트 판단 화면은 → P46 단말 화면·알림

## 7. 미결
- [미결 Q-211] 설비사별 에러코드 일괄 정리와 에러코드별 후속 처리 실제 연결은 Q-211(「에러·사유코드」 묶음)에서 정한다
