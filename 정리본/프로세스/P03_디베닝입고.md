# [프로세스] 디베닝입고

> 키워드: INB-DVN · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「입고 오더」, 「로지스올 입고 설비」, 「EWMS BIN 코드」, 「W/T」, 「설비 공통·설비사」, 「제품」, 「재고 이력·관리단위」(관리단위 전환·이력)
> **이름만 쓰는 묶음**: 「시스템」, 「AS/RS」, 「BOX Shuttle」, 「HU」, 「재고 수량」, 「LOT·제조번호」, 「단말」, 「에러·사유코드」, 「WCS 위치」, 「팔레트」, 「입고 업무 용어」
> **이어지는 프로세스**: 앞 → 없음(EWMS 디베닝 작업지시로 시작한다), 함께 → P14 공팔레트 공급(3층 입고 팔레타이징로봇이 쓰는 공팔레트를 공급한다), P05 HU 확인·생성(디베닝 팔레타이징 팔레트 ID는 HU 확인을 하지 않는다, BR-INB-DVN-006), 뒤 → P08 AS/RS 적치, P16 BOX Shuttle 적치·인출, P17 설비 접점 인계, P37 제조번호 수신·추적, P44 설비 에러·Reject 처리, 관련 → P19 GANTRY 장기 보관 재고 AS/RS 투입(EWMS 단절 때 HU 처리 원칙 REQ-EQP-GNT-023, 디베닝 적용 여부 Q-161)

## 1. 범위

디베닝 대상 중소형 BOX 제품을 1층에서 로봇으로 하역해 3층으로 옮기고, BCR 스캔 후 입고정보 속성값에 따라 팔레타이징(→ AS/RS) 또는 BOX Shuttle로 나눈다. 〔K27-OV01, G064, G065〕 EWMS 디베닝 작업지시(하역 대상 수신)로 시작해, AS/RS 적치 후 적치 W/T 확정, BOX Shuttle 적치 BOX별 W/T 확정, 또는 미도착 정리로 끝난다.

**진입 조건**

- 디베닝 경로는 제품마스터의 디베닝 대상 속성이 아니라, 디베닝 입고정보(디베닝 하역 대상) 수신과 W/T의 DEST Stock Type·BIN(9015·RCV9)으로 정한다. 〔BR-INB-DVN-033〕

## 2. 흐름

### 2-1. 하역 대상 수신과 사전 지시

1. (EWMS) 디베닝 작업지시를 하면 해당 재고를 1층 입고장(9011·RCV1)에서 디베닝설비 입고장(Stock Type 9015·BIN RCV9)으로 전환한다. WCS는 이 전환을 참고만 한다. 〔BR-INB-DVN-032, K27-OV02, G175, BR-INB-DVN-016, K27-F00.01, G066〕
2. (EWMS→WCS) 하역 작업 전에, 위 전환과 함께 디베닝 대상만 구분해 디베닝 하역 대상(속성값 포함)을 보낸다. 〔K27-F00.01, BR-INB-DVN-015, BR-INB-DVN-016, REQ-INB-DVN-013, REQ-INB-DVN-014, G066, G175〕
   - EWMS는 이때 BOX Shuttle에 적치할 수량을 미리 지정한다. 〔BR-INB-DVN-029〕
3. (WCS) 받은 시점에 팔레트 ID가 없는 재고로 등록한다. 자동화 설비 재고로 잡아 WCS 위치셀 RCV9에 두고, LOT를 채번한다. 상태는 비가용이다. 〔K27-F00.01, BR-INB-DVN-017, BR-INB-DVN-020, REQ-INB-DVN-014, REQ-INB-DVN-018, REQ-INB-DVN-017, BR-INB-DVN-032, G066, G175, K27-OV02〕
   - ⚠ 원문 불일치: WCS는 BCR 스캔 정보(제조번호)를 받아 재고(LOT 단위)를 생성하고, 시리얼 마스터 생성·이력 로그를 적재한다. 〔REQ-INB-DVN-002〕 — 재고 생성 시점이 하역 대상 수신 때(BR-INB-DVN-020·REQ-INB-DVN-017 ①)와 BCR 스캔 때로 다르다.
4. (WCS→로지스올 ECS) 받은 디베닝 하역 대상 정보를 디베닝 장비에도 그대로 전달한다. 이것이 BCR 검수의 예정정보가 된다. 〔K27-F01.00, BR-INB-DVN-009, REQ-INB-DVN-007, G066〕
5. (WCS) 입고번호·제품별로 전체 수량 중 BOX Shuttle 적치 수량(EWMS 지정)과 나머지 팔레타이징 수량을 미리 계산한다. 〔REQ-INB-DVN-024, BR-INB-DVN-030, BR-INB-DVN-003, G066, BR-EQP-BSH-015, BR-EQP-VND-023〕
6. (WCS→로지스올 ECS) 경로별 수량을 미리 전달한다. 〔REQ-INB-DVN-024, BR-INB-DVN-030, BR-EQP-VND-023, K27-IF02〕
7. (WCS→BOX Shuttle ECS(현대무벡스)) BOX Shuttle 투입 예정(입고번호, 제품, LOT, 수량)을 미리 전달한다(경로 A 사전 지시, P-02). 〔REQ-INB-DVN-024, K22-F01.01, REQ-EQP-BSH-012, BR-EQP-BSH-015, BR-EQP-VND-023, K27-IF03, K22-IF01〕

### 2-2. 하역·BCR 검수

8. (하역 로봇) 1층에서 하역하고, 3층 이송 컨베이어로 3층 BCR까지 옮긴다. 〔K27-F01.01, K22-F01.02〕
   - ⚠ 원문 불일치: WCS는 1층 하역 로봇에서 하역된 BOX를 3층으로 이송하고, 3층 팔레타이징로봇에서 팔레트화하도록 지시한다. 〔REQ-INB-DVN-006〕 — 1층 → 3층 이송을 WCS가 지시하는지, 로지스올 설비 안에서 넘기는지(K27-F01.01)가 다르다.
9. (로지스올 ECS→WCS) BCR 검수 결과를 보낸다: BOX 제품코드·제조번호, 예정정보 대조 결과(정상/REJECT), REJECT 사유. 〔K27-F01.02, REQ-INB-DVN-008〕
   - REJECT를 누가 판정하나는 「로지스올 입고 설비」 묶음(책임 경계)에, 디베닝 REJECT 사유는 「에러·사유코드」 묶음에 있다. 〔REQ-INB-DVN-008, REQ-INB-DVN-010, G082, K27-EX01〕
10. (WCS) REJECT 건은 사후 처리 대상으로 등록한다 → 5. 예외. 〔K27-F01.03, REQ-INB-DVN-008〕
11. (WCS) 정상 건은 BOX 위치를 3층 BCR로 옮기고 제조번호를 시리얼 이력에 남긴다. REJECT·미도착 BOX는 수신 때의 재고(RCV9)에 남는다. 〔REQ-INB-DVN-017〕
12. (WCS) 정상 건의 입고정보 속성값을 확인한다. 〔K27-F01.03, G064, G065〕
13. [확인필요] (WCS) 입고정보 속성값으로 팔레타이징 / BOX Shuttle 분기 목적지를 정한다. 팔레타이징 → 2-3, BOX Shuttle → 2-4. 〔REQ-INB-DVN-003〕

### 2-3. 팔레타이징 경로

14. (WCS→팔레타이징로봇 ECS) 시퀀스 버퍼 진입 시 제품, LEQ, 팔레트 ID, 팔레트별 적재 수량을 지시한다. 〔K27-IF06〕
    - [확인필요] WCS는 시퀀스 버퍼에서 동일 제품이 LEQ 수량 단위로 차례로 진입하도록 팔레타이징로봇에 지시한다. 〔REQ-INB-DVN-004〕
15. 시퀀스 버퍼 → 팔레타이징로봇 → 3층 랩핑기(랩핑) → AS/RS 3층 입고라인(P-01) → AS/RS 보관 순으로 간다. 〔K27-F01.05, BR-INB-DVN-002, BR-INB-DVN-023, G064〕
16. (팔레타이징로봇 ECS→WCS) 팔레타이징 결과(팔레트 ID, 적재 BOX 제품·수량, 제조번호(S/N))를 보낸다. 〔K27-F01.07, K27-IF08〕
17. (WCS) 관리단위를 BOX에서 팔레트로 전환한다. 위치셀(RCV9) 쪽 출고 이력과 새 팔레트 입고 이력을 같은 변경 TASK번호로 쌓아 재고에 반영한다. 관리단위 전환의 뜻(새 팔레트의 관리단위, 전환 때 그대로 두는 것)은 「재고 이력·관리단위」 묶음에 있다. 〔BR-INB-DVN-008, REQ-INB-DVN-017〕
18. (WCS→EWMS) 팔레타이징 결과로 HU 생성·PACK을 요청한다(팔레트 ID, 제품, LOT, 수량, 시리얼번호 목록). → P05 HU 확인·생성 〔K27-F01.07, BR-INB-DVN-018, BR-INB-DVN-022, BR-INB-DVN-006, BR-HU-VAL-020, REQ-INB-DVN-015, REQ-INB-DVN-020, BR-INV-WT-011, REQ-INB-DVN-017〕
    - 디베닝 팔레타이징에 쓰는 팔레트 ID는 HU 확인이 필요 없다. 규칙과 이유는 → P05 HU 확인·생성 (3. 조건·규칙). 〔BR-INB-DVN-006〕
19. (WCS→EWMS) HU 생성·PACK이 성공하면 해당 팔레트 ID로 적치 W/T 생성을 요청한다(DEST 9015·RCV9 단일 W/T). 〔K27-F01.08, BR-INB-DVN-019, BR-INB-DVN-022, REQ-INB-DVN-016, REQ-INB-DVN-020, BR-INV-WT-011, REQ-INB-DVN-017, K18-IF01, K27-IF10〕
20. (EWMS→WCS) 적치 W/T 생성 응답(W/T 번호)을 보낸다. 〔K27-F01.08, REQ-INB-DVN-020, K18-IF02, K27-IF11〕
21. (현대무벡스 ECS→WCS) AS/RS 3층 입고라인 도착(P-01) 때 목적지를 문의한다. (WCS) 팔레타이징 완료 보고로 받은 팔레트 ID와 연결해 AS/RS 적치를 지시한다. → P08 AS/RS 적치, P17 설비 접점 인계 〔REQ-EQP-VND-011〕
    - WCS가 팔레타이징 완료 보고 다음에 받는 것은 AS/RS 3층 입고라인 도착(P-01)이다. 〔BR-EQP-VND-022, BR-INB-DVN-024〕
22. (WCS→EWMS) AS/RS 적치 완료 시 적치 W/T를 확정한다. 확정되면 가용이 된다. 〔K27-F01.08, REQ-INB-DVN-017, BR-INB-DVN-021, REQ-INB-DVN-019, BR-INB-DVN-032, G175, K27-IF12〕
23. (EWMS) 적치 W/T(DEST 9015·RCV9)가 확정되면 위치를 RCV9에서 WCS1로 옮긴다. 〔BR-INB-DVN-034〕

### 2-4. BOX Shuttle 경로(경로 A)

24. 속성값 = BOX Shuttle이면 경로 A로 가고, AS/RS를 경유하지 않는다. 〔BR-EQP-BSH-001, BR-INB-DVN-003, K22-F01.02〕
25. (WCS→BOX Shuttle ECS) 투입을 지시한다. BOX 식별자를 전달하고 적치 위치는 지정하지 않는다. BOX Shuttle이 자동 할당해 적치한다. → P16 BOX Shuttle 적치·인출 〔K22-F01.03, K27-F01.06〕
26. (BOX Shuttle→WCS) 적치 완료 통보(BOX 식별자·적치셀)를 보낸다. (WCS) 이를 투입 예정과 연결해 재고를 3층 BCR → BOX Shuttle 셀로 옮긴다. 〔REQ-EQP-BSH-012, K22-F01.04, REQ-EQP-BSH-013〕
27. (WCS→EWMS) 통보를 받을 때마다 해당 BOX 1건으로 적치 W/T 생성을 요청한다(BOX 식별자, 제품, LOT, 수량, DEST 9015·RCV9 — 디베닝 팔레타이징과 같은 DEST). 〔REQ-EQP-BSH-013, BR-EQP-BSH-016, REQ-EQP-BSH-002, K22-F01.04, K22-IF04, REQ-INB-DVN-017〕
28. (WCS→EWMS) 생성 응답을 받으면 바로 확정하고, 확정 시 해당 BOX를 가용재고로 바꾼다. 〔REQ-EQP-BSH-013, BR-EQP-BSH-016, K22-F01.04, REQ-INB-DVN-017〕
    - 팔레트가 없으므로 HU 생성·PACK은 없다. 〔REQ-EQP-BSH-013, REQ-INB-DVN-017〕

| 팔레타이징 수량이 LEQ 배수가 아님 | 마지막 팔레트를 LEQ 미달 팔레트로 마감해 일반 팔레트와 같이 AS/RS에 적치한다 | 〔BR-INB-DVN-031, REQ-INB-DVN-025, K27-EX03, Q-030〕 |
| 팔레트별 적재 수량 | WCS가 입고번호·제품별 팔레타이징 수량 ÷ LEQ로 완전 팔레트 n개와 마지막 미달 팔레트 1개(잔량 수량)의 적재 수량을 미리 계산해 팔레타이징로봇에 지시한다 | 〔REQ-INB-DVN-025, BR-INB-DVN-031, Q-030〕 |
| LEQ 미달 팔레트 | HU 생성·PACK, 적치 W/T 요청, AS/RS 적치를 일반 팔레트와 같이 처리한다 | 〔REQ-INB-DVN-025〕 |
| 같은 입고번호의 디베닝 하역 대상을 다시 받음 | 최초 수신만 유효하다. 다시 받은 것은 반영하지 않고 수신 이력에 「무시(중복)」로 남긴다 | 〔REQ-INB-DVN-023, BR-INB-DVN-027〕 |
| 디베닝 하역 대상 취소·변경 | 이 프로세스에 포함하지 않는다 | 〔BR-INB-DVN-027, REQ-INB-DVN-023, Q-163〕 |
| [미결 Q-163] 디베닝 하역 대상 취소·변경의 처리(하역 시작 전·후) | 필요하면 추후 정리한다(→ 7. 미결) | 〔BR-INB-DVN-027, Q-163〕 |
| 예정 수량을 넘는 BOX | 로지스올이 REJECT한다(예정정보 없음과 같은 처리) | 〔REQ-INB-DVN-017〕 |

- ⚠ 원문 불일치(상대 기록은 다른 문서 재료): 디베닝 팔레타이징 후 DEST가 9015·RCV9인 적치 W/T 하나로 처리하는 것은, G035 「AS/RS에 넣는 입고는 자동화구역 지정」(「EWMS BIN 코드」 묶음 쪽 기록)과 다르다. 디베닝 예외인지 확인이 필요하다. 〔G175〕

## 5. 예외

### BCR 검수 REJECT

| 상황 | 처리 | 출처 |
|---|---|---|
| BCR 스캔 제품이 디베닝 하역 대상 정보(예정정보)에 없음 | REJECT한다. WCS는 검수 결과를 받는다 | 〔BR-INB-DVN-010, K27-EX01〕 |
| BCR 검수에서 제조번호 앞자리와 Product Code가 불일치 | 해당 BOX를 Reject 라인으로 토출하고 통합 Reject에 등록한다(Reject 사유코드 = Product Code 불일치). 배출처를 정하지 않으면 BOX가 라인에 남아 후속 BOX까지 멈춘다 | 〔REQ-MST-PRD-002, K13-EX01〕 |
| 모든 디베닝 REJECT(BCR 검수 결과) | WCS가 검수 결과로 받아 사후 처리 대상으로 등록한다. REJECT 건만 WCS PDA 통합 Reject 화면에서 사후 처리한다(→ 6. 기능) | 〔REQ-INB-DVN-010, BR-INB-DVN-011, K27-EX01, K27-F01.03〕 |
| 작업자 확인 | 작업자가 WCS PDA에서 REJECT BOX를 확인한 뒤 재투입한다 | 〔BR-INB-DVN-013, K27-EX01, K27-F01.03, REQ-INB-DVN-010〕 |
| 재투입 등록 | PDA에서 확인 결과(정상 확인 / 라벨 재부착 / 예정정보 확인 필요)를 입력하고 재투입을 등록한다 | 〔REQ-INB-DVN-011〕 |
| 재투입 BOX의 재검수 | BCR 검수를 다시 거친다. 정상 검수 결과를 받으면 해당 Reject 이력을 완료로 닫는다 | 〔REQ-INB-DVN-011〕 |
| 같은 BOX가 같은 사유로 다시 REJECT | 알람을 띄운다 | 〔REQ-INB-DVN-011〕 |
| 예정정보에 없는 제품 | EWMS 입고정보를 확인한 뒤 재투입한다. 확인되지 않으면 보류로 둔다 | 〔REQ-INB-DVN-011〕 |
| REJECT BOX의 재고 위치 | 수신 위치셀(RCV9)에 그대로 둔다. WCS 셀로 따로 관리하지 않고 셀 이동 이력을 남기지 않는다 | 〔BR-INB-DVN-026, REQ-INB-DVN-022, K27-EX02, Q-029〕 |
| REJECT 배출 위치 | BCR 검수 결과로 받은 REJECT 배출 위치(코드)를 Reject 이력에 저장해 PDA 통합 Reject 화면에 표시만 한다 | 〔BR-INB-DVN-026, REQ-INB-DVN-022, K27-EX02, Q-029〕 |
| 재투입 위치 | BCR 앞으로 넣어 재검수한다. 정상 결과를 받으면 정상 검수와 같이 RCV9 → 3층 BCR로 옮긴다 | 〔BR-INB-DVN-026, REQ-INB-DVN-022, K27-EX02, Q-029〕 |
| [미결 Q-029] 배출구·재투입구 | 물리 위치와 배출 위치 코드 전달 방식은 로지스올 확인이 남아 있다. 위 세 줄의 처리는 정해져 있다 | 〔K27-EX02, Q-029〕 |
| [미결 Q-169] REJECT 사유코드 목록 | 공통 사유코드 맵핑으로 정한다 | 〔K27-EX02〕 |

### 미도착·LEQ 미달

| 상황 | 처리 | 출처 |
|---|---|---|
| 입고번호의 마지막 BOX 처리 후(또는 하역 완료 후) 일정 시간이 지나도 RCV9 잔량이 남음 | 「미도착」으로 표시하고 알람을 띄운다. 작업자가 PDA에서 미도착 확정 / 대기를 고른다 | 〔REQ-INB-DVN-017〕 |
| 미도착 확정 | (WCS→EWMS) 디베닝 입고예정 잔량 취소를 요청해 정리하고, RCV9 잔량을 취소 이력으로 없앤다 | 〔REQ-INB-DVN-017, BR-INB-DVN-028〕 |
| 취소 요청 대상 | 디베닝 입고예정(입고번호)의 잔량이다. 미도착 BOX에는 적치 W/T가 없기 때문이다(적치 W/T는 팔레타이징 후 팔레트 단위) | 〔BR-INB-DVN-028〕 |
| 미도착으로 BOX가 덜 들어옴 | 미도착 확정 시점에 WCS가 그때까지 적재한 팔레트의 마감을 지시한다 | 〔REQ-INB-DVN-025, K27-EX03, K27-IF07〕 |
| [미결 Q-030] 로봇의 적재 수량 지정·마감 지시 지원 | 로지스올 확인이 남아 있다. LEQ 미달 팔레트 마감·AS/RS 적치와 WCS 사전 계산(3. 조건·규칙, 위 줄)은 정해져 있다 | 〔K27-EX03, Q-030〕 |

### EWMS 처리 실패·단절

- EWMS 처리 실패나 단절 때도 설비는 멈추지 않는다. 〔REQ-INB-DVN-017〕
- 복구 후 요청을 순서대로 다시 보낸다. 〔REQ-INB-DVN-017〕
- 복구 뒤에도 HU 생성·PACK이 성공해야 적치 W/T를 요청한다(→ 3. 조건·규칙). GANTRY의 같은 원칙(REQ-EQP-GNT-023)은 → P19. 〔REQ-INB-DVN-017〕

## 6. 기능·화면

- WCS PDA는 디베닝 BCR 검수 REJECT 건만 골라 사후 처리하는 현장 조치 기능을 제공한다. 화면은 통합 Reject 처리 화면을 쓴다. 〔REQ-INB-DVN-009, BR-INB-DVN-011〕
- 작업자가 WCS PDA에서 REJECT BOX를 확인한 뒤 재투입을 등록할 수 있다. 〔REQ-INB-DVN-010〕
- PDA에는 로지스올이 알려준 REJECT 배출 위치(코드)를 표시한다. 〔BR-INB-DVN-026〕

## 7. 미결

- [추후 정리] [미결 Q-163] 디베닝 하역 대상 취소·변경 처리 — 하역 시작 전·후 처리, 로지스올 예정정보 취소 지원 여부. 〔Q-163〕
- Q-163의 정해진 처리: 하역 대상 취소·변경은 이 프로세스에 포함하지 않는다(3. 조건·규칙). 〔Q-163, REQ-INB-DVN-023〕
- [추가 협의] [미결 Q-029] REJECT BOX 배출구·재투입구의 물리 위치와 배출 위치 코드 전달 방식 — 로지스올 확인. 〔K27-EX02, Q-029〕
- Q-029의 정해진 처리: REJECT BOX 재고 RCV9 위치셀 유지, 배출 위치 표시만, BCR 앞 재투입·재검수, 작업자 확인 후 재투입, PDA 통합 Reject 화면 사후 처리. 5절 「BCR 검수 REJECT」 표에 있다. 〔Q-029, BR-INB-DVN-026, REQ-INB-DVN-022〕
- [미결 Q-169] REJECT 사유코드 목록(공통 사유코드 맵핑). 〔K27-EX02〕
- [추가 협의] [미결 Q-030] 팔레타이징로봇의 적재 수량 지정·마감 지시 지원 여부 — 로지스올 확인. 〔K27-EX03, Q-030〕
- Q-030의 정해진 처리: LEQ 미달 팔레트로 마감·AS/RS 적치, WCS 사전 계산. 3절 표와 5절 「미도착·LEQ 미달」 표에 있다. 〔Q-030, BR-INB-DVN-031, REQ-INB-DVN-025〕
- [미결 Q-154] HU 생성·PACK에 보내는 항목. 〔K27-IF09〕
