# [프로세스] 재고 할당

> 키워드: MST-ALC · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「할당 전략」, 「재고 수량」
> **이름만 쓰는 묶음**: 「조직·재고관리체계」(화주·PLANT), 「작업지시 체계」(Task·전략 이력), 「W/T」(피킹 W/T), 「출고 오더」(출고예정), 「WCS 위치」(셀 유형·셀 상태·존), 「단말」(파워유저), 「출고 업무 용어」(사전 보충·긴급 보충·재할당), 「시스템」(Planning), 「LOT·제조번호」(출고 체크·LOT 조건), 「재고 운영 용어」(재고실사), 「팔레트」(공팔레트 공급·공팔레트 묶음)
> **이어지는 프로세스**: 앞 → 할당을 요구하는 각 프로세스(아래 3절 표), 뒤 → P33 재고 예약·보류, → P42 작업지시 생성·실행

## 1. 범위
- 작업 요구가 생겨 할당 전략을 조회할 때 시작해, 고른 재고에 예약을 걸고 결과를 돌려줄 때 끝난다
- 이 문서는 모든 할당에 공통인 단계만 둔다. 프로세스별 할당 순서(무엇부터 고르나)는 각 프로세스 문서에 있다(3절 표).

## 2. 흐름
처리 순서는 전략 조회 → 후보 조회 → 필터 → 정렬 → 보충원 순위 배분 → 예약 → 결과 반환이다

1. (WCS Planning) 작업 요구가 생긴다. 피킹 W/T 수신, 사전 보충 계획, 긴급 보충, 설비 출고 불가에 따른 재할당, 재고실사 배출, 공팔레트 공급 요청 등이다
2. (각 프로세스→WCS Planning) 각 프로세스는 할당 요구를 넘긴다(항목은 4절)
3. (WCS Planning) 화주를 지정한다(PLANT–화주 맵핑)
4. (WCS Planning) 프로세스 유형·조건으로 적용할 할당 전략을 조회한다
5. (WCS Planning) 후보 재고를 조회한다
6. (WCS Planning) 할당 전략에 따라 후보 재고를 거르고(필터) 정렬한다
7. (WCS Planning) 보충원 순위대로 수량을 배분한다
8. (WCS Planning) 할당과 예약을 처리하고 Task를 만든다. 할당 결과는 예약으로 이어진다(→ P33 재고 예약·보류)
9. (WCS Planning→각 프로세스) 할당 결과를 돌려준다
10. (WCS) 적용한 전략과 선택 근거를 전략 이력으로 남긴다

## 3. 조건·규칙

### 3-1. 전략 고르기
- 적용 조건이 겹치면 더 구체적인 전략을 쓴다
- 적용할 전략이 없을 때는 5절을 따른다.

### 3-2. 프로세스별 할당 순서 — 각 프로세스 문서에 있다
아래는 안내다. 순서 자체는 이 문서에 적지 않는다.

| 할당 요구 | 순서가 있는 곳 |
|---|---|
| 1층 GANTRY 출고·보충 | → P23 GANTRY 출고, → P22 GANTRY 사전·긴급 보충 (보충원 순서·보관호기 재고를 쓰는 순서는 → P18 GANTRY 호기 운영 §3) |
| 3층 출고 구성 | → P28 3층 출고 구성 |
| 3층 사전·긴급 보충 | → P27 3층 사전·긴급 보충 |
| 설비 출고 불가 재할당 | → P13 설비 출고 불가 재할당 |
| FULL 팔레트 출고 | → P24 FULL 팔레트 출고 |
| GTP | → P29 수작업 GTP 출고 |
| 직송 이적 | → P30 직송 이적 |
| 재고실사 배출 | → P40 재고실사 |
| 공팔레트 묶음 피킹 | → P14 공팔레트 공급 |

### 3-3. AI 제안
- AI 제안도 고정 필터(화주·출고 체크·가용·셀 상태·잠금)와 예약 규칙을 통과해야 반영한다
- 고정 필터나 예약 규칙을 어긴 제안은 기본 전략으로 대체한다
- 제안·채택·대체 결과와 지표를 전략 이력에 남긴다. 이 기록을 AI 학습·비교 자료로 쓴다

### 3-4. 위치 규칙 판정 순서 (2절 6단계의 필터)
위치 규칙의 칸은 「할당 전략」 묶음에 있다. 후보 셀은 다음 순서로 판정한다.
1. 셀 유형(위치 마스터 기본값)을 본다. 존·로케이션·셀 값을 함께 확인한다
2. 전략의 위치 규칙으로 덮어쓴다. 셀 > 로케이션 > 존 순으로 우선하고, 같은 레벨에서 겹치면 제외가 우선한다
3. 셀 상태(운영 중 임시 차단)가 앞의 모든 판정보다 우선한다
- 포함 항목이 있으면 그 범위 안만 후보로 본다

## 4. 주고받는 정보

| 송신→수신 | 시점 | 업무 항목 |
|---|---|---|
| 각 프로세스→WCS Planning | 할당 요구 때 | 프로세스 유형, 화주, 제품, 수량, LOT 조건, 마감 시각 |

- 외부 인터페이스는 없다. 출고예정·피킹 W/T가 할당 요구의 입력이다

## 5. 예외
- 적용할 할당 전략이 없는 프로세스·조건이면 프로세스 유형별 기본 전략을 적용한다
- 기본 전략도 없을 때만 할당을 보류하고 파워유저에게 알람한다
- 전략에 맞는 후보가 없거나 부족하면 그 전략의 「부족 시 동작」을 따른다
- AI 응답이 늦거나 실패하면 기본 전략으로 즉시 바꾼다. 작업은 멈추지 않는다

## 6. 기능·화면
- 할당마다 결과를 남긴다: 적용 전략 ID·버전, 후보 수, 탈락 사유(화주 불일치·가용 부족·셀 상태·잠금 등), 선택 근거(정렬 기준 값)
- 화면에서 「왜 이 재고가 선택되었는지 / 왜 할당되지 않았는지」를 조회할 수 있다
- 할당 실패 건은 부족 유형과 연결한다

## 7. 미결
- 재료에 미결 기록은 없다.
- 참고: FULL 팔레트 출고·GTP·직송 이적 정렬에서 「부분 팔레트」 단계가 있는지는 원문끼리 어긋난다(BR-MST-ALC-009 ↔ REQ-MST-ALC-004 ⑤). 그 순서는 → P24, → P29, → P30 문서가 다룬다.
