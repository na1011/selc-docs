# [프로세스] AS/RS 적치

> 키워드: EQP-ASRS · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「AS/RS」, 「팔레트」, 「W/T」, 「EWMS BIN 코드」, 「WCS 위치」, 「에러·사유코드」, 「TRASH BIN」
> **이름만 쓰는 묶음**: 「시스템」, 「작업지시 체계」, 「제품」, 「HU」, 「재고 수량」, 「재고 이력·관리단위」, 「재고 운영 용어」, 「단말」, 「입고 업무 용어」, 「출고 업무 용어」
> **이어지는 프로세스**: 앞 → P02 일반입고, P03 디베닝입고, P04 3층 수작업 이동, P11 3층 출고대 도착 팔레트 처리(재투입) / 뒤 → P35 W/T 연동, P11 3층 출고대 도착 팔레트 처리(Reject 배출 뒤), P13 설비 출고 불가 재할당, P39 재고대사 / 옆 → P10 AS/RS Bypass 이송, P12 AS/RS 용량 부족 배출, P14 공팔레트 공급

## 1. 범위
팔레트가 AS/RS 입고대(1층·3층)에 투입되어 목적지를 판별받는 때부터, 적치셀에 적치되고 적치 W/T가 확정될 때까지다.
투입 판별에서 적치하지 않기로 한 팔레트(Reject)의 3층 출고대 배출과 그 W/T 처리, 적치 실패·셀 이상도 다룬다.
Bypass는 → P10 AS/RS Bypass 이송, 용량 부족은 → P12 AS/RS 용량 부족 배출, 공팔레트 묶음 보관은 → P14 공팔레트 공급에 있다.

## 2. 흐름

### 2-1. 1층 입고대 투입 → 적치 (기본)
1. (ECS) 입구 처리와 사이즈 체크를 한다.
2. (WCS) 투입 팔레트의 팔레트 유형을 필수 값으로 확인하고, 팔레트 ID로 식별한 팔레트 유형을 제품마스터의 팔레트 유형과 대조한다.
3. (WCS→ECS) 입고 목적지를 보낸다. 목적지 전달에 팔레트 유형을 담고, WCS가 적치셀을 지정할 때만 적치셀을 함께 담는다.
4. (ECS/WCS) 팔레트 유형에 맞는 크레인 호기·Bay 안에서 적치셀을 할당한다. 적치셀을 누가 정하는지는 「AS/RS」 묶음 3-3 「셀을 누가 정하나」에 있다.
5. (ECS) 적치한다.
6. (ECS→WCS) 적치셀을 통보한다. WCS가 적치셀을 지정하지 않았으면 AS/RS가 정한 적치셀을 이 통보로 받아 반영한다.
7. (WCS) 이동 이력으로 팔레트 재고의 위치를 입고대에서 적치 셀로 반영한다.
8. (WCS→EWMS) 적치 결과를 전달해 적치 W/T를 확정하고, 확정 후 재고를 가용으로 바꾼다.

투입~적치 사이 WCS 재고의 변화는 다음과 같다. W/T 수신 시 등록과 투입 시 입고대 이동은 → P02 일반입고에 있다.

| 시점 | WCS 재고 |
|---|---|
| 적치 W/T 수신 | WCS 재고(비가용)가 1층 입고장 위치로 생긴다 |
| 입고대 투입 | 위치가 입고대로 바뀐다 |
| 적치셀 통보 | 이동 이력으로 적치 셀에 반영한다 |
| 적치 W/T 확정 | 가용으로 바꾼다. W/T 확정과 가용재고의 관계는 「W/T」 묶음에 있다 |

### 2-2. 3층 입고대 투입
3층 입고대 투입 대상 넷은 「AS/RS」 묶음 3-2 「3층 투입」에 있다. 대상마다 처리가 다르다.
- 3층 출고대 팔레트 재투입, 3층 출고 수작업 영역에서 다시 넣는 팔레트: 아래 1~5
- 3층 매거진 배출 공팔레트 묶음: → P14 공팔레트 공급
- TRASH BIN: 2-3

1. (작업자) 3층 입고대에 팔레트를 투입한다. 투입 순서는 작업자가 임의로 판단하며 WCS는 정하지 않는다.
2. (ECS→WCS) 목적지를 문의한다. 1층 입고대와 같은 방식이다.
3. (WCS→ECS) 팔레트 ID로 투입 유형을 판별해 목적지를 응답한다.
4. (WCS) 3층 출고대 재투입·3층 출고 수작업 영역 팔레트는 EWMS 적치 W/T와 HU 내역 조회로 연결한다.
5. 이후 적치는 2-1의 4~8과 같다.

3층 출고대 팔레트 재투입은 적치 W/T가 있어야 받으므로, EWMS가 적치 W/T를 생성해 줘야 한다.
적치 W/T가 없는 재투입 건은 5-3에 따라 처리한다.

### 2-3. TRASH BIN 보관 투입 (3층 입고대)
1. (작업자) 새 TRASH BIN 팔레트는 WCS 화면에서 팔레트 ID를 먼저 등록한다. 이때 TRASH BIN 재고가 생긴다(재고 단위는 「TRASH BIN」 묶음 3-3).
2. (작업자) TRASH BIN을 3층 입고대로 투입한다.
3. (ECS→WCS / WCS→ECS) 목적지 문의 → WCS가 팔레트 ID로 TRASH BIN임을 판별해 응답한다.
4. (WCS→ECS) W/T 없이 WCS가 자체 생성한 Work·Task로 AS/RS 적치를 지시한다.
5. (WCS) WCS 자체 품목으로 EWMS 반영 없이 위치 이력만 남긴다.

## 3. 조건·규칙

| 조건 | 처리 |
|---|---|
| AS/RS에 재고를 넣으라고 할 때 | 도착 위치를 자동화구역(Stock Type 0050·BIN WCS1)으로 지정한다 |
| 적치하지 못하고 다른 프로세스로 가는 재고(예: 용량 부족 배출·입고대 Reject로 3·4층 배출) | 이때만 1층 입고장·3층 출고대(Stock Type 9011·9013)로 맞춘다 |
| 크레인 호기·Bay 결정 | 제품마스터의 팔레트 유형이 기준이다 |
| 적치 범위 | 팔레트 유형에 맞는 크레인 호기·Bay 범위에서만 적치되게 한다 |
| WCS가 적치셀을 선택적으로 지정할 때 | 해당 유형의 Bay 안에서만 고른다 |
| 팔레트 ID의 팔레트 유형 ≠ 제품마스터의 팔레트 유형 | Reject로 유도한다(3층 출고대 배출, 5-1) |
| 팔레트 유형을 알 수 없거나, 2316·1960·1816이 아니거나, 대조 결과가 다를 때 | Reject로 3층 출고대에 배출한다 |
| TRASH BIN 투입 | 팔레트 유형 불일치 Reject 대상에서 뺀다. 빼지 않으면 3층 입고대에 투입한 통이 Reject되어 보관이 막힌다 |
| 이미 등록된 TRASH BIN 팔레트 ID가 다시 투입될 때 | 같은 재고 단위로 적치한다 |
| 적치 실패 후 설비가 다른 셀에 재적치하고 완료를 보고할 때 | 5-4의 1을 따른다 |

## 4. 주고받는 정보

| 송신→수신 | 시점 | 업무 항목 |
|---|---|---|
| WCS→ECS | 입고 목적지 결정 시 | 팔레트 ID, 목적지, 팔레트 유형, 적치셀(선택, 유형별 호기·Bay 범위 안) |
| WCS→ECS | Reject로 유도할 때(목적지 응답) | WCS 사유코드 |
| ECS→WCS | 적치 완료 시 | 팔레트 ID, 적치셀 |
| WCS→EWMS | 적치 통보 수신 후 | W/T 번호, 팔레트 ID, 적치 위치 |

## 5. 예외

### 5-1. 팔레트 유형 불일치 Reject
1. (WCS→ECS) 목적지 응답에 WCS 사유코드를 담아 Reject(3층 출고대 배출)로 유도한다.
2. (WCS→EWMS) 적치 W/T는 DEST BIN을 3층 출고대 도착 위치(9013·RCV3)로 바꿔 확정한다.

### 5-2. 1층 입고대 Reject (ECS 판단)
1. (ECS) Reject 여부를 판단한 뒤 에러 코드를 포함해 3층 출고대로 배출한다.
2. ⚠ 원문 불일치: 1층 입고대 Reject 팔레트는 항상 3층 출고대로 나온다.
3. ⚠ 원문 불일치: 적치 W/T를 받은 뒤 3·4층으로 토출한 입고대 Reject 팔레트는 W/T 확정 때 DEST BIN을 실제 도착 위치(3층 출고대 RCV3 / 4층 입고장 9014·RCV4)로 바꿔 처리한다.
4. (WCS) EWMS에서 받은 적치 W/T를 1층 투입 시 HU 내역 조회로 연결해 두고, 출고대 도착 시 DEST BIN을 바꿔 확정한다.
5. 출고대 도착 이후는 → P11 3층 출고대 도착 팔레트 처리.

### 5-3. 적치 W/T 없음 Reject
1. (WCS→ECS) 3층 입고대에 적치 W/T가 없는 재투입 팔레트가 올라오면 투입을 막지 않고, 목적지 응답으로 Reject(사유 = 적치 W/T 없음)를 보내 3층 출고대로 배출시킨다.
2. (WCS) 이 팔레트는 이미 EWMS상 3층 출고대(9013·RCV3) 위치라 다시 배출해도 EWMS 위치가 바뀌지 않는다. 그래서 W/T 처리·EWMS 반영을 하지 않고 WCS 위치 이력만 남긴다.
3. 1층 입고대의 적치 W/T 없음 Reject도 W/T를 확정하지 않고 사유만 표시한다.

### 5-4. 적치 실패·셀 이상
1. 적치 실패 후 설비가 다른 셀에 재적치하고 적치 완료를 보고하면, 보고된 셀로 위치를 반영한다(원래 지시 셀과 달라도 정상).
2. 최종 적치 실패를 보고하면 3층 출고대로 Reject 배출하고 통합 Reject에 등록한다. 사유는 「적치 실패」다.
3. 이때 적치 W/T는 DEST BIN 9013·RCV3로 확정한다. 갈 곳을 정하지 않으면 입고 라인에 팔레트가 남는다.
4. 셀 이상을 보고하면 셀 상태를 이동/할당불가로 바꾼다. 막지 않으면 같은 셀에 계속 할당된다.
5. 그 셀의 재고는 재고 처리 오류로 보류하고 재고대사 대상으로 등록한다(→ P39 재고대사).
6. 출고에 할당된 재고면 재할당한다(→ P13 설비 출고 불가 재할당).
7. 셀 상태 해제는 파워유저가 점검한 뒤 한다.

### 5-5. 등록하지 않은 TRASH BIN 팔레트 ID 투입
1. 등록하지 않은 팔레트 ID는 3층 입고대에서 TRASH BIN으로 판별되지 않아 Reject된다.
2. 작업자가 화면에서 등록한 뒤 다시 투입한다.
