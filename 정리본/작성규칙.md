# 정리본 작성 규칙

> 적용 대상: `묶음/`·`프로세스/` 문서. README·색인·회의안건·`_기준/`·`_추적/`은 문서에 대한 문서라 이 규칙의 대상이 아니다.
> 기준 문서([글로서리 묶음 설계 기준](_기준/글로서리-묶음-설계-제안서.md))의 묶는 기준을 그대로 따르고, 아래는 **문장을 어떻게 쓰나**를 정한다.

## 1. 원칙

**문서는 그 자체로 완결된, 지금 참인 업무 사실과 흐름만 담는다.**

- 정리본은 AI와 사람이 단독으로 읽는다. 원문 팩·작업 기록·다른 판본을 함께 보지 않는다.
- 그래서 「무엇이 참인가」만 쓰고, 「어떻게 이렇게 정리됐나」나 「예전에는 어땠나」는 쓰지 않는다. 그런 서술은 현재 사실과 섞여, 읽는 쪽이 지금 무엇이 참인지 헷갈리게 만든다.
- 문체는 현재형 평서문(「~다」)이다. 한 줄에 사실 하나를 쓴다.

## 2. 쓰지 않는 것

| 종류 | 예 | 대신 |
|---|---|---|
| **편집 과정** — 정리하면서 한 일 | 「정의가 기술이라 지웠다」, 「재료에 없어 넣지 않았다」, 「3.3 안의 하위 절로 모았다」, 「~라 남겼다」, 「~로 옮겼다」 | 지운다. 그 안에 사실이 있으면 사실만 현재형으로 쓴다 |
| **근거 문서 언급** — 판단 이유를 다른 문서로 댐 | 「(결정로그 §3)」, 「(작성보고 wb5 §3)」, 「(제안서 §7)」, 「재료에」, 「원문 표기 「…」」 | 지운다 |
| **변경 이력** — 업무 결정이 바뀐 경위 | 「설비사를 로지스올에서 현대무벡스로 바꿨다」, 「P-03은 폐기했다」, 「이전 규칙을 대체했다」, 「예전에는 … 지금은 …」, 「같은 날 …로 정정」, 「변경 이력」 절 | 지금 상태를 현재형 사실로 쓴다(3절). 이미 본문에 있으면 지운다 |
| **편집 판단** — 정리하는 쪽의 의견 | 「용어째 삭제 후보」, 「정의 생략 후보」, 「~로 옮길 후보」 | 업무 뜻이 없는 용어는 표에서 뺀다. 팀이 정할 일이면 4절의 잠정 표시를 단다 |

## 3. 변경 이력을 현재 사실로 바꾸는 법

| 이력 서술 | 현재 사실 |
|---|---|
| 3층 디팔레타이징·MIXED 설비의 설비사를 로지스올에서 현대무벡스로 바꿨다 | 3층 디팔레타이징·MIXED 설비의 설비사는 현대무벡스다 |
| P-03·P-04·P-05·P-15는 폐기했다 | 설비 접점 번호 P-03·P-04·P-05·P-15는 쓰지 않는다 |
| 용량 부족 배출의 분류를 Reject 유형으로 바꿨다 | 용량 부족 배출은 Reject 유형이다 |
| 예전에는 직송거래처도 매핑했다. 지금은 TC센터만 매핑한다 | 인도처 매핑 대상은 TC센터뿐이다. 직송은 FO 기준으로 임시 할당한다 |

- 번호가 빠진 이유를 묻지 않도록, 폐기된 번호는 「쓰지 않는 번호」라는 현재 사실로 남긴다.
- 기준 문서 §5 예 1은 폐기된 접점을 「변경 이력으로 남긴다」고 했다. 그때는 원문 팩을 함께 읽는 것이 전제였다. 정리본만 읽기로 한 지금은 이 규칙이 우선한다.

## 4. 남기는 표시 — 현재 상태를 나타낸다

아래 표시는 이력이 아니다. 「지금 확정되지 않았다」는 현재 사실이다. 지우면 미정인 것이 확정처럼 읽히므로 남긴다.

| 표시 | 뜻 |
|---|---|
| (표시 없음) | 확정 |
| `[확인필요]` | 가정으로만 쓴다 |
| `[미결 Q-NNN]` | 정해지지 않았다. 임의로 정하지 않는다. Q-NNN은 쟁점의 이름이다 |
| `[추후 정리]` · `[추가 협의]` · `[협의필요]` | 나중에 다루기로 한 미결이다 |
| `⚠ 원문 불일치:` | 서로 다른 두 내용이 함께 유효하게 남아 있다. 두 내용을 모두 현재형으로 쓰고, 어느 쪽도 고르지 않는다 |
| `(잠정 §9-N)` | 팀 회의 안건에 걸린 잠정 판단이다 |
| 「원문에 없음」 | 이 칸의 정보가 아직 없다. 비어 있다는 것도 알아야 할 사실이다 |

## 5. 써도 되는 문서 안내

- 범위·경계 문장: 「팔레트 ID의 형식은 「팔레트」 묶음이 갖는다」, 「작업 순서는 → P05에 있다」. 지금 어디에 무엇이 있는지를 말하는 현재형 사실이다.
- 머리말의 유형·확인 담당·기대는 묶음·이어지는 프로세스: 문서 형식의 일부다.
- 이유는 쓰지 않는다. 「AS/RS와 BOX Shuttle이 함께 쓰는 셀이라 이 묶음에 둔다」는 앞부분이 사실이어도 뒷부분이 편집 판단이다. 「적치셀은 AS/RS와 BOX Shuttle이 함께 쓰는 셀이다」처럼 사실만 쓴다.
