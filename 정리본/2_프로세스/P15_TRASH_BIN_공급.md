# [프로세스] TRASH BIN 공급

> 키워드: EQP-TRB · 원문 기준일 2026-11-02
> **기대는 묶음** (사실을 알아야 이해되는 것): 「TRASH BIN」, 「AS/RS」, 「설비 공통·설비사」
> **이름만 쓰는 묶음**: 「시스템」, 「GANTRY」, 「3층 디팔레타이징·MIXED」, 「운반 설비」, 「작업지시 체계」, 「단말」, 「창고 기초속성」, 「팔레트」, 「WCS 위치」
> **이어지는 프로세스**: 쓰는 공통 단계 → P09 AS/RS 인출, P11 3층 출고대 도착 팔레트 처리(3층) / 옆 → P08 AS/RS 적치(빈 TRASH BIN 보관 투입), P28 3층 출고 구성(3층 랩핑 제거 지시), P33 재고 예약·보류(빈 통 예약), P43 팔레트 작업 상태 추적(도착 지연 알람)

## 1. 범위
작업자가 TRASH BIN이 가득 찼다고 판단해 설비 내 버튼을 누를 때 시작해, AS/RS에 보관된 빈 TRASH BIN이 요청 위치(1층·3층)에 도착해 WCS가 요청을 종료할 때 끝난다.
3층 랩핑 제거 지시는 이 프로세스가 아니다(→ P28 3층 출고 구성). 빈 TRASH BIN을 AS/RS에 넣는 일은 → P08 AS/RS 적치 2-3.
가득 찬 통의 회수·비우기는 이 프로세스가 아니다. 그 책임은 「TRASH BIN」 묶음 3-4에 있다.

## 2. 흐름
1. (작업자) TRASH BIN이 가득 찼다고 판단하면 설비 내 버튼을 누른다. 만재를 누가 어떻게 판단하는지는 「TRASH BIN」 묶음 3-6에 있다.
2. (현대무벡스 ECS→WCS) 1층·3층 TRASH BIN 보충을 요청한다.
3. (WCS→현대무벡스 ECS) 수신 직후 결과를 응답한다: 접수 / 공급 불가·대기 / 진행 중.
4. (WCS) 요청 단위의 별도 작업으로 TRASH BIN 공급을 만든다.
5. (WCS) AS/RS에 보관된 빈 TRASH BIN을 선정해 예약한다(→ P33 재고 예약·보류).
6. (WCS→AS/RS ECS) 출고를 지시하고 요청 위치까지 이동 작업을 만든다(→ P09 AS/RS 인출).
7. (AS/RS → 요청 위치) TRASH BIN을 옮긴다. 이동 단계·수단은 Workflow로 설정한다.
   - 1층: AS/RS → 보충 컨베이어 → GANTRY 입구. 보충 경로이며 AMR·유인지게차 단계가 없다(이 구간이 현대무벡스 내부 인계라는 것은 「설비 공통·설비사」 묶음 3-4).
   - 3층: AS/RS → 3층 출고대 배출까지다. 3층 출고대 → 디랩핑기는 작업자가 유인지게차로 옮기며 WCS 작업지시는 없다(→ P11 3층 출고대 도착 팔레트 처리).
8. (AS/RS ECS→WCS) 출고 완료를 보고한다.
9. (ECS→WCS) TRASH BIN이 요청 위치에 도착하면 도착 알림을 보낸다(1층·3층). 도착 확인에 WCS PDA는 쓰지 않는다.
10. (WCS) 요청을 종료하고, 재고 위치를 요청 위치 로케이션으로 옮겨 위치 이력을 남긴다.

## 3. 조건·규칙

| 조건 | 처리 |
|---|---|
| 시작 조건 | 1층·3층 모두 현대무벡스 ECS의 보충 요청으로만 시작한다 |
| 3층 랩핑 제거 지시와의 관계 | 별개로 움직인다. 랩핑 제거 지시·완료 보고가 TRASH BIN 공급을 일으키지 않고, TRASH BIN 공급 상태가 랩핑 제거 지시를 막지 않는다. WCS는 TRASH BIN 공급을 랩핑 제거 지시(Workflow 단계)와 연결하지 않는다 |
| WCS PDA 호출 | 두지 않는다(1층·3층) |
| 도착 확인 | ECS 도착 알림으로 받는다. PDA 도착 스캔은 두지 않는다 |
| TRASH BIN의 AS/RS 보관·이동 | 위치 이력으로 남긴다 |
| TRASH BIN의 AS/RS 3·4층 배출 | EWMS 반영 없이 위치 이력만 남긴다 |
| 공급 경로별 팔레트 유형 제외 | 없다. 1층 GANTRY 입구가 받는 유형은 「GANTRY」 묶음 3-2에, TRASH BIN 팔레트 유형은 「TRASH BIN」 묶음 3-3에 있다 |
| 요청 처리에 붙는 규칙 | 최소 보유 수량 알람과 빈 통 없음 처리를 적용한다 |
| AS/RS의 빈 TRASH BIN 팔레트 전체 수(팔레트 유형 무관)가 층별 최소 보유 수량(「창고 기초속성」 묶음 변수) 아래로 내려감 | 알람을 띄운다 |

## 4. 주고받는 정보

| 송신→수신 | 시점 | 업무 항목 |
|---|---|---|
| 현대무벡스 ECS(1층·3층)→WCS | 작업자가 만재를 판단해 설비 내 버튼을 누를 때(보충 요청) | 요청 번호, 요청 위치(설비·호기 코드), 요청 시각 |
| WCS→현대무벡스 ECS | 보충 요청 수신 직후(응답) | 요청 번호, 결과(접수 / 공급 불가·대기 / 진행 중(같은 위치 중복 요청)) |
| WCS→AS/RS ECS | 이동 요청 수신 시 | 팔레트 ID(TRASH BIN 적재), 출고 포트 |
| AS/RS ECS→WCS | 출고 완료 시 | 팔레트 ID, 출고 포트, 완료 시각 |
| ECS→WCS | TRASH BIN 요청 위치 도착 시(1층·3층) | 요청 번호, 팔레트 ID, 도착 위치, 도착 시각(PDA 미사용) |

## 5. 예외
- 같은 위치에 진행 중인 요청이 있으면 새 요청을 만들지 않고 「진행 중」으로 응답한다.
- 진행 중 요청이 도착 지연 기준을 넘으면 팔레트 작업 상태 오류 알람을 띄워 작업자가 조치하게 한다. 첫 요청이 멈춰도 공급이 막히지 않게 하려는 것이다.
- ⚠ 원문 불일치: 빈 TRASH BIN이 없으면 요청한 현대무벡스 ECS에 공급 불가를 리턴하고 알람을 띄운다(공팔레트와 같은 방식). 요청은 대기로 두고, 빈 통이 AS/RS에 들어오면 자동으로 다시 처리한다.
- ⚠ 원문 불일치: [미결 Q-139] AS/RS에 빈 TRASH BIN이 없을 때의 처리는 미정이다.

## 6. 기능·화면
