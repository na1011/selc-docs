## 1. 재고를 고르는 순서

**왜 먼저인가:** 할당 전략의 초기 값이 다른 규칙과 어긋난다. 초기 값은 그대로 설정값이 되므로, 정하지 않으면 개발 첫날부터 한쪽으로 굳는다.

| 대상 | 안 A | 안 B | 안 C |
|---|---|---|---|
| 3층 AS/RS 팔레트 (2순위 할당·사전 보충·긴급 보충) | **잔량 최소** → 부분 팔레트 → 입고월 FIFO. 「FIFO와 충돌하면 잔량 최소 우선」 (할당 전략 초기 값, 1층 사전 보충과 같은 순서) | **입고월 FIFO** → 같은 입고월 안에서 잔량 최소·부분 팔레트 (3층 출고 구성·보충 쪽 기록) | — |
| GANTRY 보관호기 BOX | **GANTRY 보관일·LOT**가 오래된 BOX부터 | **GANTRY 보관일**만 | **LOT 입고월** → 같은 LOT면 GANTRY 보관일 (할당 전략 초기 값) |
| FULL 팔레트·GTP·직송 이적 | 수량 일치 → 잔량 최소 → **부분 팔레트** → 입고월 FIFO | 수량 일치 → 잔량 최소 → 입고월 FIFO (부분 팔레트 단계 없음) | — |

**정할 것**
- [ ] 3층 AS/RS: 안 A / 안 B
- [ ] 보관호기: 안 A / 안 B / 안 C
- [ ] FULL·GTP·직송: 부분 팔레트 단계 있음 / 없음
- [ ] 1층과 3층이 같은 순서를 쓰는가

**결정:**
- Q: 「로트 내 입고월 우선 출고(FIFO)」의 적용 범위 — AS/RS 보충원 팔레트(1층 P18 3-3·3층 P27·P28)와 보관호기 BOX(P18 3-2)인가, 3층만인가, FULL·직송 이적까지 전부인가 → A: 그때그때 설비마다 유동적으로 달라질 수 있다
- Q: 이 답을 정리본에 어떻게 적나 — 순서를 설비별 할당 전략 설정값으로 두고 ⚠를 지우나, 기본값을 정하나 → A: 설정값으로 적는다. ⚠를 지우고 「순서는 설비별 할당 전략에서 정하며 바뀔 수 있다(예: 입고월 먼저 / 잔량 최소 먼저)」로 쓴다. 처음 값은 정하지 않는다
- Q: 「Gantry 보충은 Full Pallet 만 가능」 — 부분 팔레트(LEQ 미달)를 GANTRY 보충원에서 빼는 뜻인가, 팔레트를 통째로 투입한다는 뜻인가 → A: 부분 팔레트는 GANTRY 보충에 쓰지 않는다
- Q: 「Storage Loc/제품상태/등급은 W/T로 출고지시되고 재고 관리됨」 — 사실만 적고 Q-193(출고 체크 원본 항목)은 열어 둘지, 제품상태 = Valuation Type·등급 = WCS 기준 Storage Location으로 보고 Q-193을 닫을지 → A: 제품상태 = Valuation Type, 등급 = 여러 Storage Location을 묶은 WCS 기준 Storage Location. 이 값으로 출고 체크하고 Q-193을 닫는다
- Q: 「PLT 당 최대/균일 체적 고려 피킹 지시 (현대 무벡스 몫)」 — 1층 GANTRY 로딩 옵티마이저 수행 주체를 현대무벡스로 정하는 뜻인가, 체적 계산만 현대무벡스 내부 처리인가 → A: 현대무벡스가 아니다. 삼성 SDS 또는 AI 시뮬레이션 등 별도 소프트웨어가 한다
- Q: 「3층 임시 작업장」은 3층 출고 수작업 영역(9013·RCV3)인가 → A: 같은 곳이다. P29 이름은 「출고 수작업 영역 출고」로 바꾼다
- Q: 「ORG_STO-개별STO」의 개별 STO는 ORG DO로 묶인 각 DO인가, SPLIT DO인가 → A: ORG DO로 묶인 각 DO다
- Q: 부분 해체(GTP) 대상을 「특정 기준 MD 품목(예: 1 PLT 400 BOX)」으로 정하고 「사용자 판단」 문장을 바꾸는가 → A: 품목 기준으로 정한다. 꺼내는 수량은 보충 소요량이다

## 2. 출고예정에 FO·화주가 담겨 오나

**왜 먼저인가:** 직송 GANTRY 호기 임시 할당은 「출고예정에 FO가 온다」를 전제로 설계돼 있다. 「FO가 없다는 전제의 안은 대체되었다」고까지 적혀 있다. 이 전제가 틀리면 그 흐름 전체가 성립하지 않는다.

| 기록 | FO | 화주 |
|---|---|---|
| 출고 오더 기준정보 | 온다 (「피킹 W/T에만 → 출고예정에도」로 바뀌었다는 이력 있음) | 없다 — WCS가 PLANT–화주 맵핑으로 정한다 |
| GANTRY 출고 쪽 출고예정 항목 (제품, 수량, 인도처, 시간대 Type) | 없음 | 없음 |
| 3층 출고 구성 쪽 출고예정 항목 (인도처, 화주, 제품, 수량, 시간대 Type) | 없음 | 있음 |

참고: 3층 사전 보충은 FULL 출고분을 (인도처, 화주, 제품)별로 뺀다. 화주가 있어야 성립하는 계산이다.

**정할 것**
- [ ] 출고예정에 FO가 오는가
- [ ] 출고예정에 화주가 오는가, 아니면 WCS가 맵핑으로 붙이는가
- [ ] 1층용·3층용 출고예정이 같은 인터페이스인가
- [ ] EWMS 담당 확인이 필요한가

**결정:**
- Q: 출고예정에 FO(트럭 정보)와 출고 DOCK 번호가 들어 오나, 피킹 W/T에만 들어 오나 → A: 출고예정에 온다(피킹 W/T에도 온다). 1·3층 출고예정 항목은 한 목록이다
- Q: 출고예정에 화주가 따로 들어 오나, PLANT만 오고 WCS가 화주로 바꾸나 → A: 화주가 따로 온다
- Q: 「총판·총판 온라인 = 한 화주, 삼판 = 다른 화주」로 Q-014를 닫는가, PLANT 코드 대응(L175·L1UU·L1E3)은 무엇인가 → A: 확정. 총판 = L175, 총판 온라인 = L1UU → 화주 001, 삼판 = L1E3 → 화주 002. Q-014를 닫는다

## 3. 4층 배출·4층 입고장(9014·RCV4)이 있나

**왜 먼저인가:** 이것 하나로 팔레트 경로, 배출 목적지(DEST BIN), W/T 확정 방식이 한꺼번에 갈린다. 영향 받는 문서가 11개로 가장 많다.

| 갈래 | 「3층만」 쪽 기록 | 「4층도」 쪽 기록 |
|---|---|---|
| 1층 입고대 Reject·용량 부족 배출 | 3층 출고대로만 나간다(「항상 이 라인」). DEST 9013·RCV3 | 3·4층으로 토출한다. DEST 3층 출고대 9013·RCV3 / 4층 입고장 9014·RCV4 |
| Bypass | 3층 출고대로 간다 | 4층 입고대 → 3층, 1층 → 4층(9014·RCV4) 경로가 있다 |
| 직송 이적 | 「무조건 3층으로 배출」 | 「3층(4층) 전달 완료」, 3·4층 배출 |
| BIN 구역 목록 | 9011·9013만 있고 RCV4가 없다 | RCV4(4층 입고장)가 있다 |
| 3층 수작업 이동 | 행선지 3층, 1층 → 3층 | 1층 → 3·4층 |

참고: 설비 구성은 AS/RS에 「1·3·4층 입고대·배출구」가 있다고 적고, 층별 역할은 4층을 「출고 수작업 영역」으로만 적는다.

**정할 것**
- [ ] 4층으로 배출하는 경우가 있는가. 있다면 어느 갈래(Reject·용량 부족·Bypass·직송 이적·수작업 이동)인가
- [ ] 4층 입고장(9014·RCV4)을 BIN 구역으로 쓰는가
- [ ] 현대무벡스(AS/RS) 확인이 필요한가

## 4. GTP·직송 이적 팔레트를 WCS 재고에서 언제·어떻게 빼나

**왜 먼저인가:** 재고를 빼는 시점은 양쪽 기록이 모두 「확정」 상태라, 어느 쪽도 가정으로 미룰 수 없다. 출고확정 시점과 WCS 재고 경계(자동화 영역 ↔ 수작업 영역)가 함께 걸려 있다.

| 갈래 | 안 A | 안 B |
|---|---|---|
| WCS 재고에서 빼는 시점 | 3·4층 전달 완료 때 출고확정으로 **예외 없이** 뺀다 (7건) | GTP·직송 이적분은 예외로 **W/T 확정까지 WCS 재고로 둔다** (3건) |
| 직송 이적 피킹 W/T 확정 시점 | 이적 **전**, 3층 전달 완료 때 출고확정·실적 송신. 이후 이적은 WCS 재고 밖 | 이적 **후** 출고확정 때 확정 |
| 잔량이 가는 경로 | 출고 수작업 영역으로 간다. AS/RS 재입고·**MMVT 전환 없음**. DEST 9013·RCV3 / 9014·RCV4 | 자동화 → 수작업은 **MMVT로 위치 전환** 후 출고한다. GTP·직송 이적 잔량이 그 사례로 적혀 있다 |

참고: 안 A 쪽 기록에는 「W/T 확정 전까지 WCS 관리」 예외를 **삭제했다**는 이력이 있다. 안 B가 근거로 든 요구사항 두 건은 지금 원문에 없다. 안 B가 정리되지 않고 남은 옛 기록일 가능성이 있다. 다만 확인 전까지는 판정하지 않는다.

**정할 것**
- [ ] 차감 시점: 안 A / 안 B
- [ ] 직송 이적 W/T 확정: 이적 전 / 후
- [ ] 잔량 MMVT 경유: 없음 / 있음
- [ ] 안 B 쪽 기록을 원문에서 정리(삭제)할지

**결정:**
- Q: 「GTP」는 부분 해체 보충 기능(AS/RS 팔레트 → 소요량만 수작업 피킹 → C/V → BOX Shuttle, 잔량 랩핑 후 AS/RS 재입고)만 가리키는가, P29 3·4층 출고 수작업 영역 출고도 GTP인가 → A: 보충 기능만 GTP다. P29 흐름은 GTP라 부르지 않고, 그 흐름의 차감·잔량 규칙은 보류
- Q: 1층 GANTRY MIXED 팔레트의 팔레트갈이 경로를 「AS/RS 1층 투입구 → 적치 없이 크레인 → 3층 배출」로 바꾸고 수직반송기 경로를 지우는가 → A: 인도처 팔레트 규격과 GANTRY 규격이 다를 때에만 팔레트를 바꾸려고 1층에서 3층으로 토출한다
- Q: 그때 3층으로 가는 길은 AS/RS(크레인)뿐인가, 수직반송기도 쓰나 → A: AS/RS(크레인)로만 간다. 수직반송기 길은 지운다

## 5. 가용수량에서 빼는 것과 「보류 ≤ 가용」

**왜 먼저인가:** 가용수량은 모든 할당이 쓰는 값이다. 정의가 흔들리면 할당 결과가 프로세스마다 달라진다.

- 가용수량은 **재고 − 예약 − 보류**다. 보류를 이미 뺀 값이다.
- 보류 상한의 비교 대상이 기록마다 다르다.

| 기록 | 보류 상한 규칙 | 문제 |
|---|---|---|
| 용어 정의·재고조회 | 쌓인 보류수량 ≤ 가용수량. 넘으면 재고 처리 오류 | 보류를 뺀 값과 보류를 다시 비교한다 |
| 재고조회(보류 전환) | 이번에 받은 보류 전환 수량 ≤ 가용수량. 넘으면 반영하지 않고 오류 | 비교 대상이 「이번 수량」이다 |
| 재고 관리단위 | 예약 + 보류 합계 ≤ 재고수량 | 비교 대상이 재고수량이다 |

- 가용에서 빼는 대상도 표현이 조금씩 다르다.
  - 셀 할당불가, 이동/할당불가, W/T 미확정, 작업중 재고 (용어 정의)
  - 셀 두 상태, W/T 미확정 (예약 관리·재고조회)
  - 셀 상태가 할당불가면 0 (재고 관리단위)

**정할 것**
- [ ] 보류 상한을 무엇과 비교하는가: 쌓인 보류 / 이번 전환 수량 / 재고수량(예약 + 보류)
- [ ] 가용에서 빼는 대상의 최종 목록 (작업중 재고·이동/할당불가 셀 포함 여부)
