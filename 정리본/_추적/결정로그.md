# 정리본 결정 로그 (잠정)

> 기준: [글로서리 묶음 설계 기준 — 임시문서팩 재정렬 핸드오프](../_기준/글로서리-묶음-설계-제안서.md) · 원문: 임시문서팩 기준일 2026-11-02 (C01·C02·K01~K40)
> 정리본 전체(묶음 32개, 프로세스 49개, 색인)는 위 기준 문서의 §1~§8을 그대로 적용해 만들었다. 이 로그에는 기준만으로 정할 수 없어 잠정으로 판단한 것과, §8 후보에서 바꾼 것을 남긴다.
> 이 로그의 결정은 **모두 잠정**이다. 제안서 §9의 팀 회의 안건에 걸린 것은 안건 번호를 붙였다. 회의에서 다르게 정하면 해당 묶음·프로세스만 고치면 된다.

## 1. 작업 방식

| 단계 | 한 일 |

## 2. 묶음 — 후보 28개에서 바꾼 것

| 바꾼 것 | 근거 | 안건 |
|---|---|---|
| **창고 기초속성** 묶음 신설 (조직·재고관리체계에서 분리) | 변수가 문서마다 계속 생긴다(AS/RS 적재율, BOX Shuttle 적치율, W/T 재전송, 예약 정리 시간, HU 응답 대기, TRASH BIN 보유 수량, 로딩 옵티마이저 수행 주체 등). 문서 18곳에 나오는 허브 용어라 조직 묶음 전체를 끌고 다닌다(질문 5). 변수의 **뜻**은 각 대상 묶음이 갖고, 이 묶음은 「무엇이고 어떤 변수가 있나」만 갖는다. | §9-3 |

| **재고 수량·이력**을 **재고 수량**과 **재고 이력·관리단위**로 나눔 | 수량의 뜻은 이력 세부 없이 이해되고, 이력은 수량을 이름으로만 쓴다(질문 3). 관리단위와 이력은 서로 단단히 엮여 있다(관리단위 전환 = from 출고 + to 입고 이력). 수량을 쓰는 프로세스(할당·보충)와 이력을 쓰는 프로세스(반영·대사·실사)도 갈린다(질문 4). 분류 담당 2명이 따로 같은 결론을 냈다. 확인 담당은 같을 수 있다. | §9-4 |

| AS/RS는 **한 장으로 둠** | 입출고 라인만 쓰는 프로세스는 있다. 하지만 셀 구조만 쓰는 프로세스는 없다. 「입고대는 모든 호기에 접근 가능」처럼 라인을 이해하는 데 셀 구조가 필요한 줄도 있다(§6의 두 조건 중 하나가 불충족). 셀·보관 구조는 묶음 안의 별도 절로 모았다. | §9-5 |

| 설비사는 **각 설비 묶음의 「설비사」 칸**에 적음 | 같은 사실(「AS/RS 설비사 = 현대무벡스」)이 설비사 맵핑표와 각 설비 묶음에 두 번 생기지 않게 했다(질문 2). 설비 공통·설비사 묶음은 다음 넷만 갖는다: 설비사가 누구인지, ECS가 설비사별로 따로 있다는 것, 설비 접점(P-NN)과 그 변경 이력, 「누가 누구에게 지시하나」. | §9-2 |

## 4. 프로세스 목록 — 69개 이름을 49개로

분류 담당들이 시드 목록을 쓰고 필요한 이름을 보탰다. 그 이름 69개를 다음 원칙으로 합쳤다.

- **기준정보를 화면에서 등록·수정하는 기능**은 「기준정보 관리 (MST)」 한 문서로 모았다. 창고·화주·PLANT 맵핑·창고 기초속성·거래처·위치·설비·에러코드·DOCK·LOT 생성 전략·할당 전략·Workflow 설정 13개가 여기에 해당한다. 시작~끝 흐름이 짧은 같은 꼴의 기능이라, 하나씩 문서를 두면 껍데기만 늘어난다. 대상마다 절을 나눴다.
- **EWMS에서 작업 정보를 받는 입구**는 「EWMS 작업정보 수신」 하나로 모았다. 작업정보 수신·검증, 출고 오더 수신, 입고예정정보 수신이 여기에 해당한다.
- **이름을 바꾼 것**
  - 「AS/RS 재할당」 → 「설비 출고 불가 재할당」: 적용 범위가 현대무벡스 설비 전체다(REQ-EQP-ASRS-008).
  - 「GANTRY 사전 보충」 → 「GANTRY 사전·긴급 보충」: 3층과 대칭이 되게 했다. 긴급 보충 규칙 BR-OUB-GNT-028·REQ-OUB-GNT-014·032를 이 프로세스로 옮겼다.
  - 「랩핑 제거·TRASH BIN 공급」 → 「TRASH BIN 공급」: BR-EQP-TRB-015가 두 일을 별개로 정한다. 3층 랩핑 제거 지시는 3층 출고 구성으로 갔다(예 1).
- **합친 것**
  - 출고 스케줄 수립 → 출고 배치 편성
  - 재고 보정 + 재고 반영·이력 → 재고 반영·보정
  - 통합 Reject 처리 + 설비 에러 처리 → 설비 에러·Reject 처리
  - GANTRY 인도처 매핑 관리 → GANTRY 호기 운영
  - BOX Shuttle 용량 관리 → BOX Shuttle 적치·인출
  - 전략 이력 조회 → 단말 화면·알림
- **할당 순서:** 프로세스마다 다른 순서(무엇부터 쓰나)는 각 프로세스에 둔다(§7). 모든 할당에 공통인 단계(전략 조회 → 거르기 → 정렬 → 배분 → 예약)는 「재고 할당 (MST-ALC)」에 한 번만 둔다.

## 6. SAP EWM 표준 용어 (§9-8)

다음 용어는 정의를 **남기고** `EWM 표준 — §9-8` 표시를 달았다: W/T, HU 생성·삭제·PACK·UNPACK, PLANT, Storage Location, Valuation Type, LEQ, STO, SO, DO, FO.

- 표준과 같은 뜻뿐이면 정의를 지울 수 있다.
- 무엇을 지울지는 EWM을 아는 사람이 정한다.
- 프로젝트 고유 의미는 해당 묶음에 남겼다. 예: 「W/T 생성 = WCS 재고지만 비가용」, 「HU = 팔레트 ID」.

## 7. 상태 표시 규칙

- **상태는 줄 단위로 정확히 단다.** 원문 상태가 확정인 내용과 확인필요·미결인 내용이 한 줄에 섞이면 두 줄로 나눈다.
  - 작성 중 한때 「합친 줄에는 가장 약한 상태를 붙인다」는 규칙을 썼다. 그러자 확정 규칙까지 확인필요나 미결로 보이는 부작용이 생겨, 검증 단계에서 줄을 나누는 방식으로 바로잡았다.
- **`[미결 Q-NNN]`은 그 Q가 실제로 묻는 부분에만 붙인다.**
  - 예: Q-207은 작업자 피킹 위치만 묻는다. 그래서 확정인 부분 해체 규칙(REQ-OUB-MIX-012)에는 붙이지 않는다.
- **원문 상태 칸이 비어 있는 BR(규칙)은 표시하지 않는다.** 문장 안에 Q나 확인필요가 있을 때만 그 부분에 표시한다.
- **원문에 「협의필요」라는 상태가 한 건 있다(REQ-MST-ORD-009).** C01 §1 상태 목록에 없는 값이라 `[협의필요]`로 그대로 옮겼다. K16 머리말의 REQ 개수(확정 15 / 확인필요 5 = 20)가 실제 행 수 21과 다른 원인이 이 행이다.

## 8. 원문에서 없는 것 · 범위 밖

- **2층 AS/RS:** 팩 전체에 「2층」이라는 말이 한 번도 없다. AS/RS 묶음의 「위치」 칸에 비어 있다고 적었다(§9-6).
- **짝 문서:** 제안서가 참조하는 「임시문서팩 보완 제안서」는 저장소에 없다. 그 문서 없이 진행했다.
- **원문은 고치지 않았다:** C01·C02·K01~K40은 그대로 두었다. 이 폴더(`정리본/`)는 원문 팩과 별개의 재정렬본이다.
