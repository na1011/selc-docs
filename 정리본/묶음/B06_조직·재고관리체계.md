# [묶음] 조직·재고관리체계

> 유형: 기준정보 · 확인 담당: 미정(§9-2) · 원문 기준일 2026-11-02
> 이 묶음은 창고(CDC)·화주와, EWMS PLANT·Storage Location을 WCS 창고·화주로 잇는 맵핑(재고관리체계)에 대해 늘 참인 것만 담는다. 흐름·조건·순서는 프로세스 문서에 있다.

## 1. 범위
- WCS 관리 계층의 맨 위인 창고(CDC)와 화주, 그리고 EWMS의 PLANT·Storage Location을 WCS의 창고·화주에 잇는 맵핑을 다룬다.
- 창고별 제어 옵션 변수는 「창고 기초속성」 묶음, Stock Type은 「EWMS BIN 코드」 묶음이 갖는다.
- 맵핑이 없는 데이터를 받았을 때의 처리는 → P01 EWMS 작업정보 수신, Work를 만들 때 화주를 정하는 일은 → P42 작업지시 생성·실행, 화면 등록은 → P47 기준정보 관리에 있다.

## 2. 용어
| 용어 | 뜻 | 동의어 | 비고 |
|---|---|---|---|
| 화주 | 재고·제품을 소유하는 단위(화주사). | 화주사 | |
| CDC | 물류센터(Distribution Center). | | 현재 대상 창고는 평택 CDC 하나다(3-2) |
| 창고코드 | 창고(=센터, CDC)를 식별하는 코드. | 창고 ID, 센터 코드 | EWMS 센터코드와는 맵핑으로 잇는다(3-2) |
| 창고 마스터 | WCS 기준정보의 최상위 마스터. 화주 마스터와 함께 최상위다. | 센터 마스터, CDC 마스터 | |

| PLANT | EWMS의 공장·시설 단위 코드. | 플랜트 | EWM 표준 (잠정 §9-8) |
| Storage Location | EWMS 기준 동일 모델의 제품 용도 단위 분류 코드. | SLOC | EWM 표준 (잠정 §9-8) |

## 3. 사실

### 3-1. 관리 계층
- 창고(CDC)와 화주가 WCS 관리의 최상위 단위다.
- 기준정보·재고·작업지시는 창고 아래에 속한다.
- 창고에 속하는 데이터는 반드시 하나의 창고에 속한다.
- 제품은 화주 아래에 속한다. 제품은 화주별로 관리한다.
- 재고관리체계(화주·Storage Location 맵핑)는 화주 아래에 속한다.
- 화주는 공통으로 관리한다. 창고 아래 관리 대상에 넣지 않고, 창고별로 두지 않는다.
- 창고별 운영 화주를 맵핑해 관리하지 않는다.

| 계층 | 대상 |
|---|---|
| 1 | 창고(CDC) · 화주(화주사) |
| 2 | 창고 소속 기준정보 — 창고 기초속성, 존·로케이션·셀, 설비, 오더 유형 / 화주 소속 기준정보 — 제품, 재고관리체계(PLANT·Storage Location 맵핑) |
| 공통 | 창고 아래에 두지 않는 공통 관리 대상 — 화주 |
| 3 | LOT · 재고 |
| 4 | 작업지시 — Batch · Work · Task · Action |

### 3-2. 무엇을 식별하나 (식별 기준)

**창고**
- 현재 대상 창고는 평택 CDC 하나다.
- EWMS 센터코드와 WCS 창고코드는 코드가 같든 다르든 항상 맵핑으로 잇는다.
- 같은 코드로 둘지는 맵핑 정보를 등록하는 사용자가 정한다.
- EWMS에서 받은 W/T·오더의 창고는 PLANT–센터코드 맵핑으로 식별한다. EWMS W/T가 PLANT 기준이기 때문이다.
- ⚠ 원문 불일치: 한 기록은 PLANT–센터코드 맵핑을 WCS PLANT 관리의 「WCS 맵핑 창고코드」로 등록한다고 적는다.
- ⚠ 원문 불일치: 다른 기록은 센터코드–창고코드 맵핑을 창고 마스터의 「EWMS 창고 식별값 매핑」으로 둔다고 적고, 창고 마스터 속성 기록도 이 칸을 둔다.

**화주**
- WCS는 EWMS PLANT를 화주로 맵핑해 화주를 식별한다.
- 화주 코드는 EWMS PLANT 코드와 별개인 WCS 자체 코드다(예: L175·L1UU → 001, L1E3 → 002). PLANT는 맵핑으로 화주 코드에 잇는다.
- 이 프로젝트의 PLANT 예: L175 한국총괄, L1UU 온라인, L1E3 삼성판매.
- [미결 Q-014] PLANT L175 또는 L1UU는 WCS 화주 001로 맵핑하고 보관재고를 섞어 쓴다. 맵핑 데이터 예시이며, 최종 데이터는 사용자가 정리한다.
- [미결 Q-014] PLANT L1E3는 WCS 화주 002로 맵핑하고 재고를 따로 관리한다. 맵핑 데이터 예시이며, 최종 데이터는 사용자가 정리한다.
- 평택 CDC도 화주를 구분한다.
- 재고를 통합할지 구분할지는 기능이 아니라 PLANT–화주 맵핑 데이터로 정한다. 여러 PLANT를 한 화주로 맵핑하면 통합이고, 다른 화주로 맵핑하면 구분이다.
- WCS 재고는 화주 단위(여러 PLANT 통합)로 있고, 어느 PLANT 몫인지 구분하지 않는다.
- EWMS 재고는 PLANT 기준이다. 그래서 PLANT–화주 맵핑이 바뀌어도 EWMS 재고는 바뀌지 않는다.

**PLANT 관리 (PLANT → 창고·화주 맵핑)**
- WCS에도 PLANT 관리를 둔다. PLANT별로 센터코드(창고)와 화주를 맵핑해 관리한다.
- EWMS W/T의 PLANT로 화주와 창고를 함께 정한다.

**Storage Location**
- WCS는 Storage Location을 맵핑 기준으로 따로 관리한다.
- ⚠ 원문 불일치: 재고관리체계 개요 쪽 기록은 EWMS의 PLANT·Storage Location을 WCS가 「화주·WCS Storage Location」으로 맵핑한다고 적는다.
- ⚠ 원문 불일치: [확인필요] 맵핑 마스터 요구 쪽 기록은 EWMS (PLANT, Storage Location) → WCS (PLANT, Storage Location) 맵핑 마스터를 관리한다고 적는다.
- EWMS Storage Location이 달라도 용도가 같으면 WCS 기준 Storage Location 하나로 맵핑한다(예: L167 FC01 정상품, FC02 세트구성품창고, FC03 한총e-store → 모두 L167 FC01).

### 3-3. 구성 항목
- 창고 마스터 속성: 창고코드, 창고명, 주소, 운영 여부(사용/미사용), EWMS 창고 식별값 매핑(항상 사용), 등록·수정 이력.
- 창고 마스터에는 창고 유형·운영 시간을 두지 않는다. 출고 마감 시각은 출고 마감시간 마스터에서 관리하고, TC센터는 거래처로 관리한다.
- 화주 마스터 속성: 화주 코드(WCS 자체 코드, 예: 001), 화주명, 운영 여부(사용/미사용), 등록·수정 이력.
- 화주 마스터에는 맵핑된 PLANT를 따로 두지 않는다. PLANT–센터코드–화주 맵핑에서 보여 준다.
- PLANT 관리 항목: PLANT코드, WCS 맵핑 화주사코드, WCS 맵핑 창고코드(화주 예: L175 → 001, L1UU → 001, L1E3 → 002).
- PLANT 관리 부가 항목: 적용 시작일, 사용 여부, 등록·수정 이력.
- ⚠ 원문 불일치: 위 PLANT 관리 항목에는 Storage Location이 없다. 그런데 수신 PLANT 처리 쪽 기록은 수신한 PLANT 또는 Storage Location을 「맵핑 마스터(PLANT–센터코드–화주 맵핑)」에서 찾는다고 적는다.

### 3-4. 누가 만들고 어디서 오나
- WCS는 창고(CDC) 마스터를 관리한다.
- WCS는 PLANT 마스터와 PLANT → 센터코드(창고)·화주 맵핑 마스터를 관리한다.
- EWMS에서 받지 않는 WCS 자체 생성 제품(공팔레트·TRASH BIN)용 내부 화주 하나(예: 000 'WCS 자체')를 화주 마스터에 등록한다. 이 화주도 창고별로 두지 않는다.

**EWMS 수신 원본과 실적 PLANT**
- WCS는 EWMS에서 받은 W/T·출고예정 등 작업 데이터를 가공하지 않고 그대로 보관한다(EWMS 수신 원본).
- EWMS로 보내는 실적은 수신 원본(수신 PLANT 등)을 기준으로 만든다.
- EWMS 실적은 원래 수신된 PLANT별로 나눠 보낸다. WCS가 맵핑으로 작업지시 데이터를 합쳐 가공해도 마찬가지다. W/T가 PLANT 기준이기 때문이다.
- 수신 원본은 WCS Work와 이어서 추적한다. 여러 원본 행이 한 Work에 이어질 수 있다.
- 수신 원본은 수신 일시를 함께 보관한다. 보관 기간은 「창고 기초속성」 묶음의 변수다.

### 3-5. 사용 여부·이력
- 원문에 없음. 각 마스터의 운영(사용) 여부와 등록·수정 이력 칸은 3-3 구성 항목에 있다.

### 3-6. 그 밖의 사실
- WCS 사용자 권한과 화면 조회 범위를 창고 단위로 제한할 수 있다(다중 창고 확장 대비).
- 사용자 권한별로 접근할 수 있는 화주를 제한한다. 권한이 없는 화주의 데이터(제품·재고·작업)는 조회·처리할 수 없다.

## 4. 상태 값
해당 없음.

## 5. 미결
- [미결 Q-014] [추후 정리] PLANT–센터코드–화주 맵핑 데이터는 사용자가 데이터로 정리할 예정이다(L1UU의 WCS 화주 포함). 평택도 화주 구분 기능을 두고, 통합 여부는 맵핑 데이터로 정한다는 것은 결정됐다.
