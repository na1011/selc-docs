# [묶음] 작업지시 체계

> 유형: 시스템 · 확인 담당: 미정(§9-2) · 원문 기준일 2026-11-02
> 이 묶음은 WCS 작업지시의 계층(Batch·Work·Task·Action), Workflow, 전략 이력, 팔레트 작업 상태에 대해 늘 참인 것만 담는다. 흐름·조건·순서는 프로세스 문서에 있다.

## 1. 범위
- 작업지시 계층과 각 단위가 무엇인지, Work의 구분, Workflow 설정 항목, 전략 이력 항목, Action·팔레트 작업 상태 값을 다룬다.
- Task·Action을 어느 계층(Planning·Execution)이 만드는지는 「시스템」 묶음이 갖는다. EWMS 작업 단위인 W/T는 「W/T」 묶음이 갖는다.
- 작업지시를 실제로 만들고 실행하는 순서는 → P42 작업지시 생성·실행, 팔레트 작업 상태를 따라가는 순서는 → P43 팔레트 작업 상태 추적에 있다.

## 2. 용어
| 용어 | 뜻 | 동의어 | 비고 | 출처 |
|---|---|---|---|---|
| Batch | 프로세스별 작업지시 체계의 최상위 묶음 단위. 하위에 Work를 둔다 | 배치 | [추후 정리] 세부 구체화 예정 | 〔G007〕 |
| Work | Batch 아래의 작업 단위. 받은 출고예정·W/T에 WCS가 화주·LOT 속성 등을 붙여 만든 가공 데이터다. 하위에 Task를 둔다 | 워크 | [추후 정리] 세부 구체화 예정. Work의 두 종류는 §3 | 〔G008, BR-SYS-JOB-006, REQ-SYS-JOB-005〕 |
| Task | Work 아래의 작업 단위 | 태스크, TASK | [추후 정리] 세부 구체화 예정. 만드는 주체는 「시스템」 묶음(Planning) | 〔G009〕 |
| Action | Task를 받아 Workflow에 따라 만드는 실제 설비 단위 작업지시 | 액션, 설비 작업지시 | [추후 정리] 세부 구체화 예정. 만드는 주체는 「시스템」 묶음(Execution) | 〔G010, BR-SYS-JOB-002〕 |
| Workflow | Task를 설비 작업지시용 Action으로 만드는 처리 흐름 | 워크플로 | [추후 정리] 세부 구체화 예정 | 〔G011〕 |

| 수작업 영역 팔레트 운반 | WCS 재고 관리 대상이 아닌 수작업 영역 팔레트를 자동화 설비를 사용해 운반하는 작업. 재고 작업과 다른 작업 유형이다 | 비재고 운반 | | 〔G037〕 |

## 3. 사실

### 역할
- 작업지시 체계는 Batch → Work → Task → Action이다 〔C01-4.06〕
- WCS는 작업지시를 프로세스별로 Batch → Work → Task 계층으로 관리한다 〔BR-SYS-JOB-001, K02-OV01, REQ-SYS-JOB-001〕
- WCS는 Work를 이후 할당·작업지시에 쓴다 〔REQ-SYS-JOB-005〕
- 팔레트 단위 흐름(이송 단계와 단계별 수단)은 상황에 따라 달라지므로 Workflow로 설정하고, 작업은 설정된 대로 이어진다 〔G011, BR-SYS-ARC-007, REQ-SYS-ARC-009〕
- 단계별 수행 수단(설비, AMR, 유인지게차 등)은 Workflow 설정으로 바꿀 수 있다 〔G011, REQ-SYS-ARC-009〕
- 모든 프로세스의 작업방식·전략은 전략 이력으로 남긴다 〔C01-4.06, BR-SYS-ARC-008, REQ-SYS-ARC-011〕 (잠정 §9-3)

### 책임 경계 (무엇을 관리하고 무엇을 안 하나)
- Work에는 W/T에 맵핑되어 실적을 반영하는 Work와, W/T와 무관하게 작업지시를 위해 WCS가 생성하는 Work(보충·내부 이송 등)가 함께 있다 〔G008, BR-SYS-JOB-007, REQ-SYS-JOB-007〕
- WCS는 두 Work를 모두 관리하고, Work마다 어느 쪽인지 구분한다 〔REQ-SYS-JOB-007, REQ-SYS-JOB-008〕

| 구분 | 무엇인가 | 출처 |
|---|---|---|
| Work 구분 코드 | W/T 맵핑 Work / W/T 무관 Work(WCS 생성) | 〔REQ-SYS-JOB-008〕 |
| W/T 맵핑 Work | EWMS에서 받은 피킹·이동 W/T를 가공해 만든다. 실적을 W/T에 반영한다(반영 순서는 → P35 W/T 연동) | 〔REQ-SYS-JOB-008〕 |
| W/T 무관 Work — 생성 근거 | 출고예정 기반 사전 보충, 긴급 보충, 보관호기 → 피킹호기 이동, 장기 보관 팔레타이징, BOX Shuttle 공간 확보, 공팔레트 공급·배출, 공팔레트 묶음·TRASH BIN 3층 입고대 투입, 재고실사 배출, 3층 부분 해체 재입고 등 | 〔REQ-SYS-JOB-008〕 |
| W/T 무관 Work — 근거 참조 | 근거가 된 출고예정, 설비 요청 ID, 사용자 ID, 상위 Work를 남긴다 | 〔REQ-SYS-JOB-008〕 |
| W/T 무관 Work — 실적 | EWMS에 실적을 보내지 않는다. 재고 이력·전략 이력만 남긴다 | 〔REQ-SYS-JOB-008〕 |

### 누가 누구에게 지시하나
- WCS는 Action을 ECS에 전달한다 〔REQ-SYS-JOB-002〕

### 그 밖의 사실

#### Work가 담는 정보
- Work에는 할당 전략 선택에 쓰는 프로세스 유형, 출고 유형(STO/직송), 시간대 Type, FO, 인도처를 담는다 〔REQ-SYS-JOB-006〕
- 직송 Work에는 할당한 GANTRY 호기도 담는다 〔REQ-SYS-JOB-006〕

#### Workflow 설정 항목
| 항목 | 내용 | 출처 |
|---|---|---|
| 적용 조건 | 창고, 작업 유형, 출발·도착 존·로케이션, 팔레트 유형 | 〔REQ-SYS-ARC-010〕 |
| 단계 순서 | | 〔REQ-SYS-ARC-010〕 |
| 단계별 수행 수단 | 설비·AMR·유인지게차·수작업 | 〔REQ-SYS-ARC-010〕 |
| 단계 완료 조건 | 설비 실적 / PDA 스캔 | 〔REQ-SYS-ARC-010〕 |
| 대체 단계 | 예: AMR 불가 시 유인지게차 | 〔REQ-SYS-ARC-010〕 |
| 사용 여부·적용 시작일 | | 〔REQ-SYS-ARC-010〕 |

#### 전략 이력
- WCS는 Batch·Work·Task를 생성할 때 적용한 작업방식·전략(옵션 값, Workflow, 사용자 판단 포함)을 그 작업지시와 연결된 전략 이력으로 남긴다 〔REQ-SYS-JOB-004, BR-SYS-JOB-005〕 (잠정 §9-3)
- 프로세스가 창고 기초속성 변수를 읽어 동작을 정했으면, 그 작업에 적용한 변수와 값을 전략 이력으로 남긴다. 변수 자체의 변경 이력과는 별도다 〔BR-MST-OPT-004〕 (잠정 §9-3)
- 전략 이력은 생성 시점에 남기고 고치지 않는다(추가만 한다). 전략이 바뀌면 새 이력을 추가한다 〔REQ-SYS-ARC-012〕 (잠정 §9-3)
- 전략 비교 지표와 부족 이력 집계에 전략 이력을 쓴다 〔REQ-SYS-ARC-012〕 (잠정 §9-3)

| 전략 이력 항목 | 출처 |
|---|---|
| Batch·Work·Task ID | 〔REQ-SYS-ARC-012〕 |
| 프로세스 | 〔REQ-SYS-ARC-012〕 |
| 적용 전략·작업방식 (예: 할당 우선순위, 사전 보충 전략, 3층 디팔레타이징 범위, 로딩 옵티마이저 수행 주체, 재할당 사유) | 〔REQ-SYS-ARC-012〕 |
| 적용 Workflow ID·버전 | 〔REQ-SYS-ARC-012〕 |
| 참조한 창고 기초속성 변수와 그 시점 값 | 〔REQ-SYS-ARC-012〕 |
| 결정 주체(시스템 / 사용자), 사용자 판단이면 사용자 ID·사유 | 〔REQ-SYS-ARC-012〕 |
| 적용 시각 | 〔REQ-SYS-ARC-012〕 |

#### 팔레트 작업 상태
- 팔레트 작업 상태는 작업지시 대상(설비 ECS, AMR, 수직반송기)과 WCS PDA 스캔 단계를 모두 포함한다 〔BR-SYS-ARC-010〕 (잠정 §9-7)

## 4. 상태 값

### Action 상태 (잠정 §9-7)
- 값: 생성 · 전송 · 수신 확인 · 진행 · 완료 · 실패 · 취소 〔REQ-SYS-ARC-016〕
- 값별 뜻은 원문에 없다.

### 팔레트 작업 상태 (잠정 §9-7)
| 값 | 뜻 | 출처 |
|---|---|---|
| 대기 | 현재 단계의 Action이 아직 생성·전송되지 않음 | 〔REQ-SYS-ARC-016〕 |
| 지시됨 | Action 전송·수신 확인, 출발 신호 전 | 〔REQ-SYS-ARC-016〕 |
| 이송 중 | 출발 신호 또는 진행 실적 수신, 도착 신호 전 | 〔REQ-SYS-ARC-016〕 |
| 도착 | 도착 신호 수신, 다음 단계 Action 생성 전 | 〔REQ-SYS-ARC-016〕 |
| 완료 | Workflow 마지막 단계 완료(적치 완료·출고확정 등) | 〔REQ-SYS-ARC-016〕 |
| 보류 | 사용자 보류·셀 상태 | 〔REQ-SYS-ARC-016〕 |
| 오류 | 실패 실적, 도착 지연, 신호 불일치 | 〔REQ-SYS-ARC-016〕 |

## 5. 미결
- [추후 정리] 지금은 개념만 정의한 상태다. 계층별 생성 기준·상태·번호 체계는 추후 구체화한다 〔K02-OV03〕
- [미결 Q-081] [추후 정리] Batch·Work·Task·Workflow·Action 계층별 생성 기준(프로세스별), 상태 전이, 번호 체계, Task ↔ EWMS W/T 매핑 〔Q-081〕

## 6. 변경 이력
- Task → Action 사이에 Workflow를 넣는 것으로 바꿨다(원문 표기 「Workflow 추가」) 〔REQ-SYS-JOB-002〕
