## 0. 선행 맥락 (앞 순서 관련 키워드 요약)
- **K01 SYS-ARC WCS 구성 (Planning · Execution)**: WCS 시스템 계층을 Planning과 Execution 둘로 나누고, 각각 별도 인스턴스로 분리한다. Planning은 SCP에 설치하고, Execution은 각 센터별 로컬에 설치한다.
- **K02 SYS-JOB 작업지시 체계 (Batch · Work · Task · Workflow · Action)**: WCS는 프로세스별로 작업지시를 Batch → Work → Task의 계층으로 관리하고, Task는 WCS Planning이 생성하고, WCS Execution이 Task를 받아 Workflow에 따라 실제 설비 단위 작업지시인 Action을 생성한다(SYS-ARC). Action 이후 설비 인터페이스는 오픈솔루션의 통신표준화 솔루션이 처리한다.

> 상태: 일부확정

## 1. 개요
WCS PDA는 단순 정보 조회보다 현장 작업 수행과 예외 상황 조치 중심으로 기능을 재정의한다. 바코드 스캔을 통한 화물 상태 확인, 작업 추적, Reject 처리, 긴급 조치 기능을 중심으로 요구사항을 보완한다. 입출고 예정 정보 등 관리 목적의 조회 기능은 PC와 대시보드 중심으로 검토한다.

## 2. 용어
이 문서에서 쓰는 용어(정의는 C02 GLOSSARY): WCS, Task, Workflow, Reject, 수작업 영역, EWMS PDA, WCS PDA, 대시보드, 셀 상태, HU, 팔레트 ID, 거래처, 파워유저, Action, 재고대사, 수작업 영역 팔레트 운반, W/T, AS/RS, 출고대, BCR, 설비사, 디베닝, Bypass, HU PACK, ECS, 입고대, DOCK IN, DOCK OUT, AMR, 유인지게차, 수직반송기, 출고 DOCK, 팔레트 작업 상태, 공통 사유코드, 로지스올, 적치 W/T, 후진 배출, 출고 수작업 영역, 팔레트 유형, 전략 이력, W/T 확정, 공팔레트

## 3. 프로세스 흐름
1. (작업자) WCS PDA로 화물 바코드 스캔 → 화물 상태·진행 중 작업 확인
2. (작업자) 필요 시 WCS PDA에서 Reject 처리·긴급 조치 수행
3. (관리자) PC·대시보드에서 입출고 예정·진행 현황 등 관리 목적 정보 조회
