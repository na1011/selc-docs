# [K04/40] [SYS-ERR] 통합 에러관리

## 0. 선행 맥락 (앞 순서 관련 키워드 요약)
- **K02 SYS-JOB 작업지시 체계 (Batch · Work · Task · Workflow · Action)**: WCS는 프로세스별로 작업지시를 Batch → Work → Task의 계층으로 관리하고, Task는 WCS Planning이 생성하고, WCS Execution이 Task를 받아 Workflow에 따라 실제 설비 단위 작업지시인 Action을 생성한다(SYS-ARC). Action 이후 설비 인터페이스는 오픈솔루션의 통신표준화 솔루션이 처리한다.
- **K03 SYS-UI 단말 역할 (PDA · PC · 대시보드)**: WCS PDA는 단순 정보 조회보다 현장 작업 수행과 예외 상황 조치 중심으로 기능을 재정의한다. 바코드 스캔을 통한 화물 상태 확인, 작업 추적, Reject 처리, 긴급 조치 기능을 중심으로 요구사항을 보완한다.

## 머리말
> 분류: 업무=공통(예외·에러) / 설비=공통
> 관련 시스템: WCS, ECS, EWMS | 관련 키워드: MST-EQP, EQP-VND, SYS-UI, SYS-JOB, INB-PLT, INB-DVN, EQP-ASRS, EQP-BSH, EQP-GNT, EQP-MIX, OUB-GNT, OUB-MIX, INV-SYNC
> 상태: 초안

## 1. 개요
설비사·설비마다 다른 에러코드를 WCS가 취합해 통합 에러코드로 관리한다. 에러마다 작업자 전달 메시지, 처리방법 메시지, 후행 API를 연결해 두고, 에러가 들어오면 연결된 메시지를 작업자에게 전달하고 후행 API로 후속 처리(Reject 등록, 재고 오류 표시, 재할당, Task 보류 등)를 잇는다. 설비가 감지하는 에러코드 목록은 일괄 정리할 예정이다. Reject 사유코드(공통 사유코드)도 같은 기준정보 체계 안에서 관리하는 것으로 추천한다.

## 2. 용어
이 문서에서 쓰는 용어(정의는 C02 GLOSSARY): EWMS, WCS, ECS, Task, Action, BOX Shuttle, BOX 식별자, 수직반송기, 설비사, 현대무벡스, 로지스올, 생기연, 입고대, Reject, 공통 사유코드, 통합 에러관리, 통합 에러코드, 후행 API, EWMS PDA, WCS PDA, 대시보드, 재고대사, W/T, 재할당, 팔레트 ID, 재고 처리 표준 메소드, 파워유저, W/T 취소, 긴급 보충

## 3. 프로세스 흐름
1. (WCS 기준정보) 설비사별 에러코드를 취합해 통합 에러 기준정보에 등록 — 설비사·설비·원래 에러코드 → 통합 에러코드 맵핑, 통합 에러코드별 분류·등급·작업자 전달 메시지·처리방법 메시지·후행 API·알림 대상 (BR-SYS-ERR-001·002)
2. (ECS→WCS) 에러 보고 — 설비사, 설비·호기, 원래 에러코드, 대상(팔레트 ID·BOX 식별자), 발생 위치, 관련 작업, 발생 시각
3. (WCS) 맵핑으로 통합 에러코드 결정 → 맵핑이 없으면 원래 코드로 기록하고 "미등록 에러"로 알람
4. (WCS) 에러 이력 등록(원래 코드 + 통합 코드) → 작업자 전달 메시지·처리방법 메시지를 알림 대상(WCS PDA, 대시보드, 파워유저)에 표시
5. (WCS) 후행 API 실행 — 자동 실행형은 즉시, 작업자 확인형은 PDA·PC에서 작업자가 확인한 뒤 실행
6. (작업자·WCS) 조치 완료 → 에러 상태 종료, 조치자·시각·결과를 이력으로 남김

## 7. 예외 처리
- 맵핑 없는 에러코드: 원래 코드로 기록하고 "미등록 에러"로 알람, 통합 에러코드·맵핑 관리 화면의 미맵핑 목록에 올린다 (REQ-SYS-ERR-004 ①)
- 후행 API 실패: 재시도 후 알람, 작업자가 수동으로 다시 실행할 수 있게 한다 (REQ-SYS-ERR-004 ④)
- 같은 에러 반복: 억제 시간 안에는 알림을 묶고 건수만 올린다 (REQ-SYS-ERR-004 ⑤)
