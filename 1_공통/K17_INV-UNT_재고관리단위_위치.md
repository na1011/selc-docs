## 0. 선행 맥락 (앞 순서 관련 키워드 요약)
- **K02 SYS-JOB 작업지시 체계 (Batch · Work · Task · Workflow · Action)**: WCS는 프로세스별로 작업지시를 Batch → Work → Task의 계층으로 관리하고, Task는 WCS Planning이 생성하고, WCS Execution이 Task를 받아 Workflow에 따라 실제 설비 단위 작업지시인 Action을 생성한다(SYS-ARC). Action 이후 설비 인터페이스는 오픈솔루션의 통신표준화 솔루션이 처리한다.
- **K05 MST-CTR 창고(CDC) 마스터**: 창고(CDC)를 화주(MST-OWN)와 함께 WCS 관리의 최상위 단위로 관리한다. 로케이션·설비 등 기준정보와 재고·작업지시 관리는 창고 아래에, 제품·재고관리체계(화주·Storage Location 맵핑)는 화주 아래에 속한다.
- **K11 MST-LOC 로케이션 / 위치코드**: EWMS BIN 코드(RCV9, WCS1, AMVT, MMVT)와 WCS 위치셀 사이의 매핑 기준, 설비 물리 위치 코드 포맷을 정의한다. EWMS는 수작업 영역과 자동화 설비 영역 전체 재고를 관리하며, 자동화 설비 영역은 BIN(로케이션) 단위로 크게 묶어 관리한다.
- **K13 MST-PRD 제품마스터**: 입고 경로, 보관설비, 출고설비를 결정하는 제품마스터 속성을 정의한다. Product Code는 제품마스터의 하위 속성이며, 이를 이용한 제조번호 정합성 체크도 여기서 다룬다.
- **K14 MST-LOT WCS LOT 관리**: WCS는 보관재고가 섞이지 않도록 LOT 생성 전략에 정한 LOT 속성 조합으로 LOT를 채번하여 재고를 구분한다. 창고코드·화주·제품코드는 필수 속성으로 항상 포함하고, 나머지 속성은 창고별로 선택한다.
- **K15 MST-SN 제조번호(S/N) 관리**: 평택 CDC는 LOT 생성 전략에서 제조번호를 LOT 속성으로 선택하지 않는다(물류 작업지시 효율 저하 우려, 후보 속성으로는 존재, MST-LOT). 대신 시리얼 마스터를 두어, 시리얼번호가 입고되어 최초 생성될 때, 설비로부터 시리얼번호 단위 결과 실적을 받을 때, 출고하면서 시리얼번호 단위 검수 결과를 받을 때 이력 로그를 쌓아 추적한다.

## 1. 개요
WMS 기본 사상에 따라 물리적 위치(존·로케이션·셀)와 논리적 관리단위(UOM 관리단위)를 분리한다. 논리적 관리단위는 invn_id로 식별하며 BOX일 수도, 팔레트일 수도 있다. invn_id는 아이템 UOM 레벨에 따라 1레벨(낱개 BOX) 현재 셀, 2레벨 중포장 ID, 3레벨 팔레트 ID를 쓴다. 재고는 UOM 기준 중포장 단위로도 팔레트 단위로도 보관할 수 있고, invn_id는 보관 단위의 ID이며 상하위 구조는 두지 않는다. 재고는 창고 ID(wh_id), invn_id, lot_id를 키로 관리하고, invn_id의 위치는 별도 위치 테이블에서 관리한다. 그래서 팔레트 단위로 이동해도 재고는 바꾸지 않고 위치만 바꾼다. 재고는 직접 수정하지 않고 이력(입출고 이력·재고 이동 로그·재고 상태 이력)을 쌓으며, 이력 적재와 재고 반영은 같은 트랜잭션에서 처리하고 이력마다 이력 유형 코드를 붙인다. 재고 처리는 유형별로 표준화한 재고 처리 표준 메소드로만 하고, 각 프로세스는 해당 유형의 파라미터만 바꿔 호출한다. 즉 어떤 업무 프로세스도 재고를 바로 갱신하지 않고 표준 메소드를 골라 호출하며, 재고의 모든 변경(수량·위치·관리단위·LOT·예약·보류·상태)은 이력으로 남는 구조로 설계한다(§3 재고 처리 구조).

## 3. 프로세스 흐름
데이터 구조:
| 구분 | 대상 | 키·주요 항목 |
| --- | --- | --- |
| 물리 위치 | 존(Zone) → 로케이션 → 셀(위치셀) | 셀 ID (MST-LOC) |
| 논리 관리단위 | invn_id — BOX(1레벨, 셀) / 중포장(2레벨) / 팔레트(3레벨) 중 보관 단위 | wh_id + invn_id |
| 재고 | invn_id에 담긴 LOT별 수량 | 키 wh_id + invn_id + lot_id / 팔레트 ID, 제품코드, 수량 |
| 위치 | invn_id의 현재 위치 | invn_id → 셀 (별도 테이블) |

처리:
1. 팔레트 단위 이동(적치·배출·설비 간 이송): (WCS) 위치 테이블의 셀만 변경, 재고 레코드는 변경하지 않음
2. 팔레트에 여러 제품을 담는 경우: 팔레트 ID, 제품코드, 수량, 위치(셀)로 관리
3. 셀에는 서로 다른 invn_id를 함께 둘 수 있음 (MST-LOT BR-MST-LOT-016)
4. 재고는 중포장 단위(invn_id = 중포장 ID)로도 팔레트 단위(invn_id = 팔레트 ID)로도 보관하며, invn_id 상하위 구조는 두지 않음 (BR-INV-UNT-025, 평택 CDC는 중포장 미사용)

재고 처리 구조 (BR-INV-UNT-011·013~016·018, REQ-INV-UNT-016·020~022·024·026):
```
[업무 프로세스] 입고·적치 / 출고·출고확정 / 보충·이송 / 관리단위 전환 / 예약·보류 / 실사·대사 / LOT 속성 변경 …
 │ 재고·이력 테이블에 직접 쓰지 않음 — 처리 유형에 맞는 표준 메소드를 골라 파라미터만 넘김
 ▼
[재고 처리 표준 메소드] 입고 | 출고 | 이동 | 전환 | 상태 변경
 │ 한 트랜잭션: 검증 → 대상 재고 행 잠금 → 이력 적재 → 재고·위치 반영 → 커밋 (하나라도 실패하면 전체 롤백)
 ▼
[이력] 입출고 이력 · 재고 이동 로그 · 재고 상태 이력 (모든 이력에 이력 유형 코드·변경 TASK번호)
[결과] 재고(wh_id + invn_id + lot_id) · 위치(invn_id → 셀) · 예약·보류 수량
 │
 ▼ 커밋 후 후속 연계: EWMS 실적·W/T, 시리얼 이력 로그, HU 연동 (이력 유형 규칙에 따름)
```

| 표준 메소드 | 남기는 이력 | 재고 반영 | 대표 호출 지점 |
| --- | --- | --- | --- |
| 입고 | 입출고 이력(증가) | 재고 행 생성·증가, 위치 등록 | AS/RS 입고 등록, 디베닝 RCV9 등록, BOX Shuttle 적치, 재고 보정(+) |
| 출고 | 입출고 이력(감소) | 재고 행 감소·종료 | 출고완료 확정, 3·4층 배출 차감(EQP-ASRS), 재고 보정(−) |
| 이동 | 재고 이동 로그(from·to 1건) | 팔레트: 위치만 변경 / BOX 단위 설비: invn_id(셀)가 바뀜 | AS/RS 적치·재입고, 설비 간 이송, GANTRY·BOX Shuttle 셀 간 이동 |
| 전환 | 입출고 이력(from 출고 + to 입고, 같은 변경 TASK번호) | 관리단위·LOT가 바뀌고 총량 유지 | 디팔레타이징, 팔레타이징, MIXED 출고 구성, GTP 분할, 팔레트갈이, HU PACK·UNPACK, LOT 속성 변경 |
| 상태 변경 | 재고 상태 이력 | 예약·보류 수량, 재고·셀 상태 | 예약 생성·소진·해제, 보류, 작업중, W/T 미확정·확정, 이적 중, 셀 상태 |

- 재고·위치·예약 수량을 바꾸는 경로는 표준 메소드 하나뿐이다. 업무 프로세스 코드에서 재고·이력 테이블을 직접 갱신하지 않는다.
- 이력은 지우거나 고치지 않고, 잘못 쌓인 이력은 반대 이력으로 정정한다(REQ-INV-UNT-023 ⑥). 현재 재고는 이력을 처리한 결과이므로, 이력으로 언제든 재고의 변경 과정을 추적할 수 있다.
- 새 프로세스는 이력 유형 코드와 그 규칙만 추가하고 표준 메소드는 고치지 않는다(REQ-INV-UNT-025 ③).

## 7. 예외 처리
- 표준 메소드 처리 중 하나라도 실패하면 이력과 재고 모두 반영하지 않는다(전체 롤백, REQ-INV-UNT-020). 호출한 프로세스는 오류를 받아 재시도·알람을 처리한다
- 수량 합산 결과가 마이너스가 되면 처리하지 않는다(REQ-INV-UNT-014)
- 같은 요청이 다시 들어오면(설비 실적 재전송 등) 성공한 요청은 한 번만 반영하고 앞선 결과를 돌려주며, 실패한 요청은 다시 처리한다(REQ-INV-UNT-025 ⑥)
- 재고 보정 감소로 예약이 재고를 넘으면 넘는 예약을 해제하고 재할당·긴급 보충으로 넘긴다(REQ-INV-UNT-025 ④)
