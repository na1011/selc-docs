## 0. 선행 맥락 (앞 순서 관련 키워드 요약)
- **K01 SYS-ARC WCS 구성 (Planning · Execution)**: WCS 시스템 계층을 Planning과 Execution 둘로 나누고, 각각 별도 인스턴스로 분리한다. Planning은 SCP에 설치하고, Execution은 각 센터별 로컬에 설치한다.
- **K02 SYS-JOB 작업지시 체계 (Batch · Work · Task · Workflow · Action)**: WCS는 프로세스별로 작업지시를 Batch → Work → Task의 계층으로 관리하고, Task는 WCS Planning이 생성하고, WCS Execution이 Task를 받아 Workflow에 따라 실제 설비 단위 작업지시인 Action을 생성한다(SYS-ARC). Action 이후 설비 인터페이스는 오픈솔루션의 통신표준화 솔루션이 처리한다.
- **K04 SYS-ERR 통합 에러관리**: 설비사·설비마다 다른 에러코드를 WCS가 취합해 통합 에러코드로 관리한다. 에러마다 작업자 전달 메시지, 처리방법 메시지, 후행 API를 연결해 두고, 에러가 들어오면 연결된 메시지를 작업자에게 전달하고 후행 API로 후속 처리(Reject 등록, 재고 오류 표시, 재할당, Task 보류 등)를 잇는다.
- **K12 MST-EQP 설비 기준정보 · 팔레트 유형**: WCS는 자동화 설비를 기준정보(설비 기준정보)로 관리한다. 설비마다 장비 특성(작업 단위, 처리 능력, 적재 제약, 투입·배출 포트, 사용 팔레트 유형 등)이 다르므로, 공통 속성과 설비 유형별 속성을 정의하여 작업지시 대상 ECS 결정, 설비 배정, 설비 접점 처리, 공팔레트 공급의 기준으로 사용한다.

## 1. 개요
자동화 설비별 설비사를 정의하고, 설비사가 다른 설비 사이에서 BOX/팔레트가 인계되는 설비 접점의 발생 위치를 정리한다. 설비사별로 ECS가 따로 있으므로 설비 접점에서는 설비끼리 직접 연동하지 않고 WCS가 중간 처리한다. 모든 설비 접점에 WCS 중간 처리 원칙을 적용한다. 같은 설비사 설비 사이의 인계는 해당 설비사 ECS 내부에서 처리한다.

| BR-EQP-VND-021 | 3층 랩핑기·디랩핑기 | 현대무벡스의 3층 랩핑 제거 설비 명칭을 '3층 디랩핑기'로 한다(이전 '3층 랩핑기'). 로지스올 설비에 3층 랩핑기(랩핑 설비)가 있으며, 디베닝 팔레타이징 팔레트를 AS/RS 3층 입고라인 투입 전에 랩핑한다. P-01은 3층 랩핑기 → AS/RS 3층 입고라인이다 |
| BR-EQP-VND-022 | 3층 랩핑기 WCS 관여 | WCS는 3층 랩핑기에 관여하지 않는다. 랩핑 지시·완료·실패 보고가 없고, 랩핑 실패 처리는 로지스올 내부에서 한다. WCS는 팔레타이징 완료 보고 후 P-01 도착(AS/RS 3층 입고라인)만 받는다 |
| BR-EQP-VND-023 | P-02 인계 방식 | 사전 지시로 한다. WCS가 디베닝 하역 대상 수신 시 EWMS 지정 BOX Shuttle 적치 수량으로 경로별 수량을 계산해 로지스올·현대무벡스 ECS에 미리 전달한다 (INB-DVN BR-INB-DVN-030) |
| BR-EQP-VND-024 | ATL 하역 후 이송 | ATL이 하역한 팔레트는 무조건 AMR로 이어진다(유인지게차 대체 없음). ATL → AMR은 생기연 내부 인계다. AMR이 AS/RS 1층 입고대까지 갈지 대기존까지 갈지는 Workflow로 설정한다 |
| BR-EQP-VND-025 | AFL 운영 범위 | AFL은 Workflow 이송 수단의 하나로 둔다. AMR처럼 생기연 ECS로 작업지시하는 수단이며, 실제 사용 구간은 Workflow 설정으로 정한다 |
| BR-EQP-VND-012 | 3층 디팔레타이징·MIXED 팔레타이징 설비사 | 현대무벡스로 변경한다(이전 로지스올). 3층 출고 구성에 AS/RS 팔레트를 쓸 때 디팔레타이징 배출라인 → 디랩핑기 → 디팔레타이징 → MIXED 팔레타이징이 모두 현대무벡스 설비다. 이에 따라 P-03·P-04·P-15는 현대무벡스 내부 인계로 폐기하고, P-14는 송신 설비사를 현대무벡스로 한다 |
