# [C01] 평택 CDC WCS 요구사항 — 공통 컨텍스트

> 이 문서는 AI에게 가장 먼저 입력하는 공통 문서다. 다음에 C02 GLOSSARY를 입력하고, 이후 맡은 키워드 문서(K01~K40)를 순서대로 입력한다.
> C01·C02는 작업자가 나누지 않고 모든 세션에서 똑같이 일괄 입력한다.
> 기준일: 2026-11-02 · 키워드 40개 · 원본: 요구사항 정리 저장소 `requirements/keywords/`

## 1. 이 자료의 성격과 읽는 규칙
평택 CDC(물류센터) **WCS 개발 요구사항**을 업무·설비 키워드 단위로 나눈 자료다. 여러 작업자가 키워드를 나눠 맡아 순서대로 입력한다.

AI는 다음 규칙으로 읽는다.
1. **공통 문서와 키워드 문서로 나뉜다.** C01(이 문서)·C02(GLOSSARY)는 모든 키워드의 전제다. 키워드 문서 하나가 한 단위이며, §2에는 그 문서에서 쓰는 용어 이름만 적고 정의는 C02를 따른다. 같은 용어는 모든 문서에서 같은 뜻이다.
2. **상태를 구분한다.**
   - `확정`: 업무 담당이 확정한 내용 → 설계 기준으로 쓴다.
   - `확인필요`: 초기 자료에서 옮겼거나 추천한 내용 → 가정으로만 쓰고, 쓸 때는 "확인필요 기반"이라고 표시한다.
   - `Q-NNN`(미결): 아직 결정되지 않은 사항 → 임의로 결정하지 않는다. 가정이 필요하면 가정임을 밝힌다.
   - `[추후 정리]`·`[추가 협의]`: 나중에 다루기로 한 미결이다.
3. **주체를 구분한다.** 요구사항 주체가 EWMS·ECS인 항목은 WCS 개발 범위 밖이며, WCS와의 인터페이스 협의 대상이다.
4. **참조는 코드와 ID로 한다.** 키워드 코드(예: `MST-PRD`), 규칙 ID(`BR-MST-PRD-005`), 요구사항 ID(`REQ-MST-PRD-002`), 미결(`Q-025`), 설비 접점(`P-01`).
   - 아직 입력되지 않은 키워드를 참조하면 아래 §6 키워드 지도로 대략 이해한다. 추측한 부분은 추측이라고 표시한다.
5. **문서끼리 모순되면** 어느 한쪽을 임의로 택하지 말고 두 ID를 함께 보고한다.
6. 이 입력용 자료에서는 **폐기된 항목과 출처(날짜·작성 근거) 표기를 뺐다.** ID 번호가 중간에 비어 있는 것은 정상이다.
7. 각 키워드 문서 맨 앞의 "선행 맥락"은 앞 순서 관련 키워드의 요약이다. 이미 그 키워드를 입력받았다면 원문을 우선한다.

## 2. 프로젝트와 시스템 계층
- **EWMS**(상위 시스템, 개발 범위 외) → **WCS**(개발 대상) → **ECS**(하위, 설비사별 설비 제어 시스템).
  - EWMS: 수작업 영역 + 자동화 설비 영역의 전체 재고, 입출고 오더, W/T 생성·확정, HU 채번, 도크 배정. 자동화 설비 영역은 BIN 단위로 크게 묶어 관리한다(BIN·Stock Type).
  - WCS: 자동화 설비 영역 재고만 관리한다(BIN 안의 설비 내 상세 재고·위치). 설비 작업을 지시·제어하고, W/T 확정으로 EWMS와 재고를 맞춘다.
  - ECS: 설비사가 운영. WCS 작업지시를 받아 설비를 움직이고 실적을 보고한다.
- **설비사**: 현대무벡스, 로지스올, 생기연. 수직반송기는 설비사 미정(다른 설비사로 가정).
- **설비 접점(P-NN)**: 설비사가 다른 설비 사이의 인계 지점. 모두 WCS가 중간 처리한다.
- 외부 연계: FIS(역수입 차량 입문계획), 아마노시스템(게이트 관리), SDS(로딩 옵티마이저).

## 3. 설비 구성
| 설비사 | 설비 |
|---|---|
| 현대무벡스 | AS/RS(1·3·4층 입고대·배출구), BOX Shuttle, GANTRY(피킹호기·보관호기, 소속 1층 MIXED 팔레타이징로봇 포함), 보충 컨베이어, 사이즈 체크, 3층 랩핑 제거(디랩핑기), 3층 디팔레타이징 로봇, 3층 MIXED 팔레타이징로봇 |
| 로지스올 | 디베닝 장비(1층 하역 로봇, 3층 BCR, 시퀀스 버퍼), 3층 입고 팔레타이징로봇, 3층 이송 컨베이어 |
| 생기연 | AMR(1층만 사용), ATL(상차·하차), AFL |
| 미정 | 수직반송기 |

- 층별 역할: 1층 = 하역장·입고·AS/RS 입고대·GANTRY·출고 DOCK, 3층 = 디베닝(BCR)·팔레타이징·BOX Shuttle·디팔레타이징·MIXED 팔레타이징·출고대·출고 수작업 영역, 4층 = 출고 수작업 영역.
- 3·4층 팔레트 이동은 유인지게차로 하며 WCS 작업지시가 없다.
- 팔레트 유형: 2316, 1816, 1960. 팔레트 ID 앞 4자리로 식별한다.

## 4. 핵심 설계 원칙 (여러 키워드에 공통)
- **최상위 관리 단위**: 창고(CDC)와 화주. 기준정보·재고·작업지시는 창고 아래에 속하고, 제품은 화주사별로 관리한다(제품 PK = 화주 + 제품코드).
- **EWMS 연계**: 창고는 PLANT–센터코드 맵핑으로 식별한다. EWMS 수신 원본을 보관해 실적은 원래 수신 PLANT별로 나눠 보낸다. 맵핑이 없는 데이터를 받으면 보류하고 알람을 띄우며, 맵핑을 등록한 뒤 다시 처리한다.
- **재고 구조**: 존·로케이션·셀 = 물리 위치, invn_id = 논리 관리단위(보관 단위의 ID — 팔레트 ID, 또는 BOX 단위 설비는 셀 코드). 재고 키 = 창고 + invn_id + LOT, 위치는 별도로 관리한다. 재고를 직접 수정하지 않고 유형별 재고 처리 표준 메소드로 이력을 쌓은 결과로 반영하며, 잘못 쌓인 이력은 반대 이력으로 정정한다.
- **수량 단위(UOM)**: 제품 UOM은 3레벨(1 낱개 BOX, 2 중포장단위 — 평택 미사용, 3 팔레트 = LEQ)이다. 재고·이력·EWMS 수량은 모두 1레벨(BOX = EA)로 다룬다.
- **가용 제외 표현**: 재고 상태를 따로 두지 않는다. 작업은 예약(작업 유형), 보류는 보류 레코드(사유), 셀 사용 제한은 셀 상태로 표현한다. 가용 = 재고 − 예약 − 보류. W/T 미확정은 W/T 작업이 잡은 예약으로 본다. 보류 재고는 이동·전환을 막는다(재고 보정·재고실사는 예외).
- **WCS 구성**: Planning(Task 생성)과 Execution(Task → Workflow에 따라 설비 작업지시 Action 생성)으로 나뉜다. 작업지시 체계는 Batch → Work → Task → Action이다. 작업방식·전략은 전략 이력으로 남긴다.
- **출고 배치**: 피킹 W/T는 출고 배치 차수가 확정된 뒤에만 할당·작업지시가 생긴다(배치 확정 = 관문). 출고예정은 사전 보충에만 쓴다.
- **수작업 영역 ↔ 자동화 설비** 사이 정보는 EWMS PDA로 처리하고 EWMS가 WCS에 실시간 통보한다. 단, 출고완료 확정은 WCS가 제공한다.
- **W/T**: EWMS 작업 단위. WCS가 EWMS에 W/T 생성을 요청하는 경우는 디베닝 적치 W/T와 GTP·직송 이적 잔량 이동 W/T뿐이다. 경로는 W/T DEST(Stock Type·BIN)로 정한다.
- **예외 처리**: 설비 에러·Reject 사유는 통합 에러코드로 관리하고, 에러마다 작업자 메시지·처리방법·후행 API를 연결한다.
- **단말 역할**: WCS PDA = 현장 작업·예외 조치(스캔, Reject 처리 등), PC·대시보드 = 관리·조회.
- **재고대사**: 설비사·WCS가 같은 시점 재고 스냅샷으로 비교하고, EWMS와는 BIN별 합산으로 대사한다. 불일치는 WCS만 단독 보정한다.
