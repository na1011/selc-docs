# 평택 CDC WCS 요구사항 — AI 입력 작업자 가이드

> 기준일: 2026-11-02 · 키워드 40개 · 이 폴더는 `python3 _tools/build_ai_pack.py`로 키워드 원본에서 자동 생성한다. **이 폴더의 파일은 직접 고치지 않는다.**

## 1. 목적
WCS 요구사항을 키워드별로 나눠 여러 작업자가 AI에 입력한다. 입력 순서와 문서 형식을 맞춰, 작업자가 바뀌어도 AI가 앞의 맥락을 이어서 이해하게 하는 것이 목표다.

## 2. 폴더 구성
| 파일 | 용도 | 입력 |
|---|---|---|
| `00_작업자가이드.md` | 이 문서 (사람용) | 입력하지 않음 |
| `C01_공통컨텍스트.md` | 읽는 규칙·시스템 계층·설비·설계 원칙·키워드 지도 | **공통 일괄 입력** — 모든 세션 첫 번째 |
| `C02_GLOSSARY.md` | 전체 용어 정의 (용어·정의·동의어·관련 키워드) | **공통 일괄 입력** — 모든 세션 두 번째 |
| `1_공통/` · `2_입고/` · `3_출고/` · `4_기타업무/` | 키워드 문서 K01~K40 (대분류 폴더별, 입력 순서 번호 = 파일 번호) | 작업자별로 나눠 맡은 대분류를 번호 순서대로 |

- **공통 부분(C01·C02)**은 작업자가 나누지 않는다. 모든 작업자가 자기 세션에서 똑같이 한 번씩 입력한다(합계 약 46,340자).
- **키워드 부분(K01~)**만 작업자별로 나눈다. 용어 정의는 C02로 옮겼으므로 키워드 문서 §2에는 용어 이름만 있다.

각 키워드 문서의 형식:
- 맨 앞: 입력 순서, 묶음, 선행·후행 키워드, 상태 요약
- "선행 맥락": 앞 순서 관련 키워드의 요약 → 앞 키워드를 입력하지 않은 세션에서도 이어서 이해할 수 있다
- 본문 §1~§8: 키워드 원본 (폐기 항목·출처 표기 제외, §2는 용어 이름 목록)
- 맨 끝: `[코드 끝 · 다음 입력: …]` 표시 → AI가 문서 경계를 안다

## 3. 대분류 · 묶음과 순서
키워드는 4개 대분류로 나눈다: **공통**(시스템·공통·기준정보 — 재고 기본·보관설비 포함), **입고**, **출고**, **기타업무**(재고 운영·차량·야드). 순서는 의존 관계를 따르며 공통이 항상 먼저다.

| 대분류 (폴더) | 순서 | 묶음 | 키워드 수 | 분량(자) |
|---|---|---|---|---|
| 공통 — 시스템·공통·기준정보 (`1_공통/`) | K01~K25 | A, B, C, D, E | 25 | 238,685 |
| 입고 (`2_입고/`) | K26~K29 | F | 4 | 47,122 |
| 출고 (`3_출고/`) | K30~K35 | G | 6 | 72,801 |
| 기타업무 — 재고 운영·차량·야드 (`4_기타업무/`) | K36~K40 | H, I | 5 | 32,667 |

- 기본 분담은 대분류 단위(4명)다. 입고·출고·기타업무 작업자도 공통 대분류의 내용을 전제로 하므로, 필요하면 앞 작업자의 인계 요약을 받는다.
- 공통 대분류는 분량이 커서 한 세션에 다 넣기 어렵다. 나눠 맡을 때는 아래 묶음 단위로 나눈다.

- 분량은 글자 수다. 한 세션에 너무 많이 넣으면 앞 내용을 놓치기 쉬우니, 작업자 한 명이 한 세션에 넣는 양은 묶음 2~3개 정도가 적당하다.
- 묶음 순서를 바꾸지 않는다. 앞 묶음을 맡은 작업자가 먼저 시작한다.

## 4. 입력 방식
두 가지 중 하나를 고른다.

**방식 A — 한 세션을 이어서 사용** (AI 대화창 하나를 작업자들이 차례로 이어서 씀)
1. 첫 작업자가 `C01`과 `C02`를 입력한다.
2. 각 작업자는 맡은 키워드를 번호 순서대로 입력한다.
3. 자기 차례를 마치면 "인계 요약"을 받아 다음 작업자에게 넘긴다(대화가 길어져 새 세션으로 옮길 때도 쓴다).

**방식 B — 작업자별 새 세션** (작업자마다 자기 대화창)
1. `C01`과 `C02`를 입력한다.
2. 앞 작업자에게 받은 "인계 요약"이 있으면 입력한다(첫 작업자는 생략).
3. 맡은 키워드를 번호 순서대로 입력한다.
4. 마치면 인계 요약을 받아 다음 작업자에게 넘긴다.

## 5. 프롬프트 템플릿
`{ }` 부분만 바꿔 쓴다. 문서는 파일 첨부 또는 본문 붙여넣기 모두 된다.

**① 세션 시작 (C01·C02 공통 입력)**
```
평택 CDC WCS 개발 요구사항을 키워드 단위로 순서대로 입력하려고 합니다.
첨부한 C01 공통 컨텍스트와 C02 GLOSSARY를 먼저 읽고, C01 §1 읽는 규칙을 이 대화 내내 지켜 주세요.
용어는 C02 정의를 기준으로 하고, 키워드 문서 §2에 나오는 용어도 C02 정의로 읽어 주세요.
이해했으면 "준비 완료"와 함께 시스템 계층과 핵심 원칙을 5줄 이내로 요약해 주세요.
이후 키워드 문서를 K번호 순서대로 보냅니다.
```

**② 인계 요약 입력 (방식 B, 두 번째 작업자부터)**
```
다음은 앞 작업자가 입력한 키워드({K01~K08})의 인계 요약입니다.
이 내용을 앞 키워드의 맥락으로 기억하고, 이어서 {K09}부터 입력합니다. "확인"이라고만 답해 주세요.
{인계 요약 붙여넣기}
```

**③ 키워드 입력 (문서마다)**
```
[{K12}/40] {MST-PRD} 키워드 문서입니다.
작업: {이번 작업 지시 — 예: 기능 명세 작성 / 테이블 설계 / 인터페이스 명세 / 화면 설계 / 테스트 시나리오 / 우선 읽고 이해만}
- 확정 요구사항만 설계 기준으로 쓰고, 확인필요·미결(Q)은 가정이라고 표시해 주세요.
- 선행 키워드와 연결되는 지점과, 모순되거나 빠진 것으로 보이는 부분은 따로 정리해 주세요.
```
"이해만"으로 넣을 때는 답변을 짧게 받는다:
```
[{K12}/40] {MST-PRD} 키워드 문서입니다. 읽고 ① 핵심 3줄 ② 선행 키워드와의 연결점 ③ 미결 개수만 답해 주세요.
```

**④ 인계 요약 요청 (자기 차례를 마칠 때)**
```
지금까지 입력한 키워드의 인계 요약을 만들어 주세요. 다음 작업자가 새 대화에 그대로 붙여넣습니다.
형식:
1. 입력한 키워드: K번호·코드 목록
2. 키워드별 핵심 결정 (각 3줄 이내, BR·REQ ID 포함)
3. 키워드 간 연결 (데이터·인터페이스·순서)
4. 작업 중 정한 가정과 산출물 요약
5. 남은 미결(Q)과 모순 의심 사항
```

## 6. 주의
- K번호 순서를 지킨다. 뒤 키워드가 앞 키워드의 용어·규칙을 전제로 한다.
- AI가 확인필요·미결 항목을 확정처럼 다루면 바로잡는다.
- AI 작업 중 나온 새 결정이나 모순 의견은 이 폴더를 고치지 말고 요구사항 담당자에게 전달한다. 원본(`requirements/keywords/`)에 반영한 뒤 이 폴더를 다시 생성한다.
- 기준일이 다른 폴더의 파일을 섞어 쓰지 않는다. C01·C02도 키워드 문서와 같은 기준일의 것을 쓴다.
