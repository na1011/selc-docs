# 결정 반영

사용자가 준 결정을 그대로 옮기지 않는다. 무엇을 바꾸는지 스스로 따져 본 뒤, 해석을 사용자에게 확인받고 반영한다.

새 문서·절·표시는 입력이나 사용자의 답이 필요로 할 때 만든다. 정리 작업 자체를 관리하려고, 또는 내가 추론한 하위 질문을 남기려고 만들지 않는다. 새로 만들었으면 보고에 이유를 적는다.

## 진행 체크리스트

응답에 이 목록을 복사해 진행 상황을 표시한다.

```
- [ ] 1. 입력 성격 확인
- [ ] 2. 주장 단위로 나누기
- [ ] 3. 정리본과 대조
- [ ] 4. 해석 검증
- [ ] 5. 확인 게이트 — 답을 받기 전에는 6으로 넘어가지 않는다
- [ ] 6. 확인된 항목만 반영
- [ ] 7. 반영 검증과 보고
```

## 1. 입력 성격 확인

- 사용자가 반영을 요청한 입력은 확정 결정으로 본다.
- 입력에 「~할 수 있다」「검토」처럼 확정되지 않은 표현이 있으면 그 주장만 5에서 묻는다.

## 2. 주장 단위로 나누기

- 한 줄에 주장 하나를 둔다. 원문 문구는 고치지 않고 그대로 옮긴다.
- 주장마다 ID를 붙인다. 예: `안건1-전제1`, `안건2-3`.
- 한 문장에 조건과 결론이 함께 있으면 나눈다.

## 3. 정리본과 대조

- 주장마다 관련 문장을 찾는다. 검색 범위는 `정리본/1_묶음`·`정리본/2_프로세스`, 그리고 `정리본/_관리/`의 모순보고·회의안건·결정로그다.
- 입력 낱말로만 찾지 않는다. 주장이 말하는 동작(무엇을, 어디서 어디로, 누가)으로도 찾는다. 같은 동작이 다른 이름으로 있으면 「이미 있음」 또는 「구체화」다. 예: 「GTP로 BOX Shuttle 보충, 잔량 재입고」 = P28 3-4 「부분 해체」.
- 주장마다 다음 중 하나로 분류한다.

| 분류 | 뜻 |
|---|---|
| 신규 | 정리본에 없는 내용 |
| 이미 있음 | 같은 내용이 이미 있다. 고칠 것이 없다 |
| 구체화 | 기존 문장을 바꾸지 않고 세부를 더한다 |
| 충돌 | 기존 확정 문장과 다르다 |
| 쟁점 종결 | 기존 `⚠ 원문 불일치`·`[미결 Q-NNN]`·`[확인필요]`를 정한다 |

- 충돌과 쟁점 종결은 바뀌는 기존 문장을 문서·절 번호와 함께 그대로 인용한다.

## 4. 해석 검증

- 뜻이 둘 이상으로 읽히는 말을 모두 찾는다. 용어는 `정리본/_관리/용어소속.tsv`와 해당 묶음의 용어 표에서 정의를 확인한다.
- 그 말마다 해석 후보를 두 개 이상 세우고, 각 후보로 읽었을 때 정리본의 어느 문장과 맞고 어느 문장과 어긋나는지 적는다. 그다음 추천안을 고른다.
- 추천 해석은 원문 문구가 가리키는 대상까지만 정한다. 같은 쟁점의 다른 갈래는 추천하지 않고 보류로 둔다. 예: 1층 GANTRY 팔레트 경로에 대한 답으로 M-03 (c) 전체를 닫지 않는다.
- 입력에 없는 사실은 만들지 않는다. 책임 주체, 경로, 운반 수단, 코드 대응(예: 이름 ↔ PLANT 코드), 시점이 해당한다. 필요하면 질문으로 올린다.
- 한 주장을 반영하면 다른 문서에 남는 옛 문구가 무엇인지 미리 적는다.

## 5. 확인 게이트

- [확인표_양식.md](확인표_양식.md)대로 확인표를 만들어 응답에 보여 준다.
- 묻는 질문은 입력이 답하는 안건 파일(`정리본/_관리/회의안건/`)의 해당 안건 `**결정:**` 칸 아래에 한 줄씩 적는다. 대화가 끊겨도 이 줄에서 이어 간다. 해당하는 안건이 없을 때만 새 안건 파일을 만든다.
- 묻는 것은 두 종류뿐이다.
  - 기존 확정 문장 변경, `⚠ 원문 불일치` 삭제, 미결 Q 종결. 항목마다 따로 묻는다.
  - 어느 해석을 고르느냐에 따라 고칠 본문이 달라지는 낱말
- 나머지 행은 「이렇게 반영합니다」로 두고, 사용자가 표를 보고 고칠 수 있게 한다.
- AskUserQuestion은 한 번에 4개 이하로, 바뀌는 문서가 많은 질문부터 묻는다. 추천안을 첫 선택지로 두며 「(추천)」을 붙인다. 남은 질문은 다음 호출로 이어서 묻는다.
- 답을 받으면 그 줄을 `- Q: … → A: …`로 고친다.
- 사용자가 답하기 전에는 안건 파일 말고는 `정리본/`의 어떤 파일도 고치지 않는다. auto 모드여도 같다.

## 6. 확인된 항목만 반영

- `정리본/_관리/작성규칙.md`를 따른다. 현재형 사실만 쓰고, 근거 문서나 변경 경위는 쓰지 않는다.
- 확인된 항목은 현재 사실로 쓴다. 그 사실을 맡은 문서에 쓰고, 다른 문서의 옛 문구는 지우거나 「→ Pnn」 안내 한 줄로 줄인다.
- 입력이나 답이 직접 열어 둔 것만 `[확인필요]`로 본문에 남긴다. 해석하다 생긴 하위 질문은 본문에 달지 않는다.
- 쟁점을 닫으면 관련 줄(`⚠` 두 줄, 「차이:」 줄, 미결 절 항목)을 지우고 확정 문장 하나로 바꾼다.
- 보류된 항목은 본문을 고치지 않는다. 안건 파일에 `→ 보류`로 남는다.
- 모순보고: 다 닫힌 M-NN은 항목을 지우고 건수를 고친다. 일부만 닫혔으면 남은 갈래로 줄인다.
- 결정로그: 정리본 구조(묶음·용어·프로세스 목록)를 바꾸는 결정일 때만 쓴다.
- 정리본 본문과 `_관리/` 기록은 따로 커밋한다.

## 7. 반영 검증과 보고

- 다음을 검증하고, 걸리면 고친 뒤 다시 검증한다.
  - 바뀐 사실이 다른 문서에 옛 문구로 남아 있는지 `grep -rn`으로 찾는다.
  - 새로 단 `→ Pnn` 링크와 절 번호가 실제로 있는지 확인한다.
  - 작성규칙 2절의 「쓰지 않는 것」이 들어갔는지 확인한다.
- 고친 문서의 표시 수(`⚠ 원문 불일치`·`[확인필요]`·`[미결`)를 반영 전후로 센다.
- 보고는 주장 ID별로 한다: 반영한 문서·절, 보류한 항목과 이유. 표시 수 변화와, 늘었거나 새 문서·절을 만들었으면 그 이유를 함께 적는다.
- main 반영은 따로 묻는다(`/merge-main`).
